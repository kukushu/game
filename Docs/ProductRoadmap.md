# 湾岸：产品开发路线

目标：制作可独立运行、可维护、可商业发行的原创城市建造游戏。目前状态仍为玩法原型，不是可发布版本。以下阶段是验收顺序，不是交付日期或销量承诺。

## 暂定范围与待定决策

- 暂以 Windows 单机、键鼠操作作为开发基线；发行平台、目标玩家、售价和最低配置尚未确定。
- 首版优先做好小型城市的建设与经营循环。地图规模和人口上限应由性能实测决定。
- 需要明确区别于现有城市游戏的核心体验，再决定公共交通、产业、灾害等扩展的优先级。
- 当前程序生成建筑、地表纹理和界面均为占位内容，不能视为最终美术品质。

## 1. 工程基础与小型演示

采用 Unity Terrain 承载地表，使用独立 Mesh 生成道路和地基。模拟数据保持与场景对象解耦。将目前集中在 HarborCityGame 的输入、镜头、界面、存档、场景渲染逐步拆开，每次保留能运行的版本。

验收：干净检出项目可重复编译；独立 Windows 构建可运行；起伏地形上选点和建设正确；相机与 UI 不互相抢输入；退出、重新进入和读档无异常。保留有代表性的旧存档作为回归样本。

## 2. 可玩的完整小场景

完善道路图、路口、实际寻路、通勤与货运，让布局影响城市表现。建立需求、人口、就业、服务和财政的可解释关系。增加明确目标、失败后的恢复方式、新手引导、暂停菜单和设置。

验收：不了解开发过程的测试者可以独立完成一个完整的建设目标，理解城市问题并通过操作改善它。车辆不能仅用于装饰。

## 3. 存档、性能与内容生产

引入地图标识、地图版本和存档迁移；保存使用可恢复的写入流程，加入备份恢复与自动存档。地形生成参数变更不得悄悄改变旧城市地貌。将自制及引入资源的来源与使用范围记录在资产清单中。

在选定的基准电脑上记录帧耗时、模拟更新耗时、GC 分配、峰值内存、加载和保存时间。先测量，再决定对象池、合批、分块、LOD 或 Job System 等优化。不要仅凭编辑器帧率认定发行包性能。

验收：容量上限下的城市连续运行、反复读档和重启通过；最低配置及帧率目标有可复现测量依据；正式美术、音频、字体、UI 与反馈形成一致体验。

## 4. 发布候选版

- 在独立发行构建中验证 shader、Terrain、中文字体、输入、画质设置及存档路径。
- 完成旧版本升级、异常退出、低磁盘空间、损坏存档、不同分辨率和硬件的检查。
- 确认第三方资源及依赖的来源、版本和使用条件；发布前核实届时适用的平台与引擎条款。
- 整理发行包版本号、变更记录、已知问题、反馈渠道、故障诊断和补丁回滚方式。
- 产品名称、商店资料、发行账号与对外发布需在内容实际准备完成后单独处理。

## Terrain 迁移记录

地形现由 513×513 高度图驱动 Unity Terrain，使用 TerrainCollider 选点，4 个 TerrainLayer 混合草地、高地、岩石和沙岸。道路仍是贴地 Mesh，建筑保持水平地基。地形保持固定坐标和生成公式，不修改 v1 城市存档字段。

已存在的手动 Terrain、grass/water 材质不由生成器覆盖。目前程序生成的地形数据是运行时资源，Play 中手绘修改不会持久化；正式地图编辑、资产化和地图版本保存仍待完成。地形虽然换成 Terrain，植被仍是原型物体，尚未迁移到可批量渲染的生产资源。

自动检查可验证高度查询、射线碰撞、地表权重、示例城市坡度和道路顶点；它们不能替代独立构建、真实交互、性能及长期运行测试。
