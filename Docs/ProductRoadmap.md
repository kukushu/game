## 第一阶段：道路与分区建设

先打通外部连接 → 铺设基础道路 → 形成街区 → 沿路划定住宅、商业、工业用途。分区是土地规划数据；建筑继续使用独立实体、稳定 ID 和世界坐标。

复用现有道路图、直线与曲线施工、吸附、交叉分割和拆除。新增道路沿线的分区地块、有效性与占用判断、涂画和取消分区、道路变更后的更新及存档。第一阶段先使用一种基础道路；升级等工具逐步补齐，不把改外观冒充道路升级。

处理方向、建筑占地、路口避让、曲线与重叠地块、已有实体占用。先核对尺度，再决定分区尺寸与地图容量，不能直接把原作米制尺寸套到目前原型世界单位上。详见 [第一阶段实施方案](RoadsAndZoningPlan.md)。

可重复验收：新建空城，从城外连接铺路，建设矩形、斜向和弯曲街区，分别划 R/C/I，取消部分分区，增加支路、拆除和撤销道路，保存、退出、重启、读取。核对预览、可开发土地和分区是否一致。此阶段只验收规划；区域尚未生长时人口为零属于未接入第二阶段，不宣称已经可以经营城市。

## 第二阶段：建筑生长与基础经营

完成划区 → 建筑逐步生长 → 真实居民迁入 → 就业、通勤与货运 → 财政收入和维护 → 扩建。提供可解释的 R/C/I 需求与建设条件，启动过程不能陷入“没有住宅就没有岗位需求，没有岗位就不能迁入”的闭环。

普通住宅、商业、工业由分区生长，公共设施由玩家建设。调整政府直接支付普通住宅建设费、收取居民租金、承担私人住宅维护及给每座工厂注资等自定义规则，接入与基准一致的税收和公共支出。旧规则先隔离或停用，再启用新规则，不叠加两套财政。家庭住房、成员、岗位、库存和实际出行继续作为实体关系使用；不再扩展原创家庭经济深度。

接入基础电力、供水与污水，以及开局必须具备的服务。具体税率、需求公式、初始资金和生长速度在核实后决定，未确认的内部机制标明近似实现。不能把原型的“到岗、工厂现金和工资支付”约束直接宣称为原作规则。

保留必要的施工、用途与密度识别、入住及实际道路活动反馈；画风、模型美化与景观打磨后置。

可重复验收：从空地连接道路、布置水电、划区，观察建筑生长、居民迁入、就业和城市活动，检查收支后扩建一片街区；暂停供给、恢复供给并观察后果；保存重启继续经营。验收对象是一座能持续发展的城市。

## 第三阶段：市政服务、成长与管理压力

按所选版本开局和解锁顺序补齐垃圾、医疗、消防、警察、教育、死亡处理等服务，完善需求、土地价值、建筑等级、密度、办公、预算、政策与里程碑。具体顺序需按实际基准核对；第二阶段运行必需的服务提前实现。

设施要有范围、能力和与模拟对应的活动，缺失或不足有玩家能理解的后果。保留现有住宅摘要 → 家庭列表 → 选中家庭 → 成员详情结构；调试面板服务于验证，不重新定义主经营界面。

可重复验收：发展到连续多个解锁节点，处理服务不足、收支压力和建筑发展问题，观察建设、预算及布局调整如何改善城市。与原作逐项比较触发条件、操作与反馈。

## 第四阶段：交通建设深度与空间扩展

扩展道路类型、宽度、车道、单行、桥隧、高速连接、公共交通、对外货运和城区扩张。道路升级要修改实际通行规则；桥隧必须正确处理高度连接，不能让立交错误相交。改善路口、复杂地形施工及编辑体验。

先建立车道与路口通行基础，再分项加入已确认的 TM:PE 能力；修路 MOD 按确认后的工具能力排期。MOD 增强单列验收，不反向替代本体分区和城市发展规则。

可重复验收：用单行、升级、立交及公交线路处理同一片城区的交通问题，核对路径、方向、停靠、运力与货物到达；扩张后保存重启复验。不能仅凭模型外观宣布完成。

## 第五阶段：逐项补齐与整体打磨

回到复刻对照表补齐功能与体验差距，包括尚未排入前面阶段的本体内容；完整清单持续核对，不能把“小城循环”当成完整本体。持续完善建筑种类、密度层次、地图、界面、音效和操作反馈。

独立 Windows 构建验证新建、长期经营、保存读取、不同分辨率、异常退出恢复和性能。记录基准电脑、城市规模、帧耗时、模拟耗时、内存、加载与保存时间，再做有依据的优化。编辑器能运行不等于独立版本通过验收。

不要求兼容此前开发存档；本阶段新存档必须可靠，包含地图标识、版本及必要配置，不能因地形公式改变而悄悄改变旧城市。发行包、资产来源与补丁流程另行完成，不用复刻体验验收代替发行验收。
