# 工厂生产与基础资金流（存档格式 8）

本文记录当前原型的自定义工业实现，不作为一代复刻的规则依据。2026-10-09 起开发优先级以 [开发路线](ProductRoadmap.md) 为准；现金注资、付薪与生产约束等机制将在对应阶段核对、隔离或调整，本轮尚未修改代码。

工厂复用现有建筑、岗位、居民通勤、货车与家庭住房选择。现金和累计经营收支保存在 `FactoryState`，使用原有 F3 观察台；没有贷款、股东、税务、动态市场或破产重组。

## 资金流

- 固定第一版价格：原料每份 ¥8，商品每件 ¥45，每批加工必要成本 ¥2。集中在 `FactoryState`，不是效率或亏损惩罚参数。
- 新建工厂费用为原有建设费 ¥60 加经营资金 ¥1,200。后者从城市财政实际扣除并进入工厂现金，记录为资本投入而非经营收入。没有自动补款。
- 原料货车满足路线、入口和容量条件、确实能发车后支付采购费；现金不足时缩小订货量，买不起一份时不发车。不在订货时入库，不在到货时重复扣费。途中损失是已经付费的真实损失，不自动退款。
- 成品发车只扣库存，实际被商业接收或送达城外时才收款。拒收数量、失败运输和返程不产生收入。商业采购方暂用简化外部经营资金，出口收入来自城外；本版未增加商业企业账户，不能宣称全城经济完全封闭。
- 居民真实在岗时，按合同日薪 / 480 分钟计算应付工资，并立即从工厂现金扣除实际可支付部分，转入个人 `factoryWageCredit`。日末只把余额中的整元转入家庭储蓄，小数继续保存；已付工资不因换工作、拆厂或迁出而消失。商业工资以及旧档已挣工资仍使用原有外部工资来源。
- 缺料、成品仓满时仍可用现有现金支付短期在岗工资，现金会真实减少。现金不足时只支付余款，不创造负现金、不形成无限工资或自动垫款；记录本步未付金额 `unpaidWages`，该字段是累计诊断值，本版不实现欠薪债务追偿。有效加工只使用本步实际付薪对应的劳动分钟。
- 新批次开始时支付 ¥2 加工成本，再领用原料；买不起时不开批次。已付成本的未完成批次随存档保留。
- 现金为零时暂停采购、付薪和加工，未出发者不再去该厂，上班途中的居民沿现有道路返家，在厂居民也发起真实返程。回家后释放就业关系、触发家庭工作评估。道路断开会继续等待，不瞬移回家。
- 建筑实体和物理岗位编号保留；无资金的岗位不允许招聘，也不计入资金可用岗位。住房/工作候选按可用现金除以现有雇员数估计可支付日薪，上限是合同日薪。没有按亏损天数固定删岗位的规则。
- 滞销导致无销售收入、成品仓满停产，留岗工资继续耗费有限现金，随后影响采购、加工和就业。即使无现金，已有商品仍可正常发货；实际售出恢复现金后可以重新采购和招聘，不自动恢复已解除的合同。
- 拆厂时移除实体，日志保留关闭前的经营记录，不退回经营资本；已经转给个人的工资余额照常日结。运输失败不会给拆除的工厂继续记销售收入。

工厂现金核对：`cash = capital + salesRevenue - rawCosts - wageCosts - productionCosts`。经营盈余为销售收入减以上三种成本，资本不算收入。全城工厂累计实付工资等于所有居民累计收到的工厂整元工资加未日结工资余额；拆除工厂的累计工资合入 `retiredFactoryWages`，继续参与核对。

## 生产与库存

- `IndustrialBuilding.factory` 保存原料、加工进度、累计在岗/加工时间、产量及环境历史。成品使用 `IndustrialBuilding.goodsStock`，商业库存使用 `CommercialBuilding.stock`。
- 原料容量 24，成品生产上限 24。每件商品消耗 1 份原料和 60 个实际工人分钟；多人可以共同完成一批。
- 居民实际到厂、处于本人工作时段、持有该厂岗位且没有在途任务，才能贡献劳动。工资由工厂现金承担；缺料或仓满时可能有有限的在岗工资，但无有效加工。
- 开始加工时领用原料，未完工进度存档。缺工、缺料或仓满期间不积攒未来可用的劳动。
- 工厂有雇员，且原料与已订在途原料总和低于 8 时，调度进口；每车最多 8 份。订货时不入库，到达后才入库。已有交通调度和拥堵会影响送达。
- 商业缺货优先向本城工厂提货，不足时进口商品；工厂库存达到 20 时也会尝试出口。发车从供应方扣货，到达才交付。回程不重复交货。
- 断路车辆等待；沿用货运 120 模拟秒失败期限。失败货物退回仍存在且有空间的供应方，否则计入 `lostGoods/lostRaw`。拆除的库存及在制品也明确记为损失。
- `produced/consumed/imported/shipped` 是累计计数；`shipped` 指装车发出的总量，包括之后可能退货的运输，不代表净销售或收入。

## 环境与住房

实际加工工人分钟产生噪声、污染强度，4 个连续加工工人对应强度 1；不依赖建筑岗位是否填满。噪声和污染分别以 60、720 游戏分钟的时间尺度衰减。按距厂 24、45 世界单位线性衰减至零。

住宅周围 12 世界单位内的实际货车（含排队和空车返程）形成重型交通暴露记录，以 120 游戏分钟平滑。停留卸货阶段不重复计道路车流。拆除工厂后残留环境记录逐步消退。

每户分别具有噪声、污染、货车敏感度。候选住房评分减去：`噪声×敏感度×18 + 污染×敏感度×30 + 货车暴露×敏感度×12`。原有房租、空间、隐私、通勤、储蓄和租约规则保留。环境只是取舍的一部分，靠近工厂不会被硬性禁止居住。

这些距离、加工配方、衰减时间和评分权重是第一版调参常量；环境数值是活动暴露指标，不是物理浓度。目前没有风向或污染健康损害。经营结果来自真实收支，不额外施加效率惩罚。

## 调试与日志

- F3 → 经营 → 工厂详情：工厂状态、原料、成品、加工进度、产量、环境、现金、资本投入、实售数量、销售收入、三类支出、累计盈余、未付出勤和资金核对差额。
- F3 → 家庭 → 详情：每户环境敏感度、候选住房暴露值及环境扣分。
- F3 → Debug 主动开启并导出 Trace：保留 `factory.capital/raw_paid/sale`；`factory.day` 含库存、加工和累计收支，可用相邻两日差值分析每日产量与经营收支。每日 CSV 新增 `factoryWages/externalWages`，区分资金来源。
- 可检查：只有岗位无到岗者时产量为零；原料货车未到时无原料；移除出货道路最终仓满停产；重新开通后继续加工；不同家庭对同一环境的扣分不同。

## 存档兼容

仅支持格式 8。保存使用 `CitySaveData/BuildingSaveData` 显式 DTO，加载按类型恢复 `IndustrialBuilding` 与 `FactoryState`，完整保存现金、库存、工资余额、在制批次和在途货物。旧格式直接拒绝，没有迁移、补款或简化自动产货分支。每步临时劳动不保存，模拟步结束后归零。

验证入口：`Tools/Verify.ps1`，覆盖实际交付收入、采购预付、运输失败、仓满与缺料、现金耗尽、工资守恒、重新招聘、建厂投入、拆除与新档续算。Unity 菜单 `Harbor → Validate entity architecture and native saves` 检查真实 JsonUtility 的实体、库存、行程与确定性续算。
