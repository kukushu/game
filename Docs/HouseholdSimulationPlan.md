# 家庭选择驱动的城市模拟：第一版实现方案

状态：2026-09-28 的历史设计方案。当前实现和格式 8 数据模型以 README、CitizenJobs.md 与 BuildingArchitecture.md 为准；下文保留当时的设计讨论。

2026-10-09 起目标改为先复现一代城市建设与经营，见 [开发路线](ProductRoadmap.md)。下文的市政住房开发、政府收租与原创家庭选择定位不再约束后续路线；适用的成员和住房实体关系继续复用。

## 目标与默认取舍

玩家建设道路、住宅、工作场所和公共服务，居民决定就业，家庭决定租住哪里。人口、租金收入和街区变化必须从实际入住、雇佣和交易中汇总，不能再从建筑等级直接产生。

第一版定位为“市政住房开发与城市经营”：新住宅由城市持有，建设费与维护费由城市承担，实际收到的租金进入财政。商业和工业提供有数量限制的岗位。先实现几百户可以观察、保存和复现的家庭，不以增加可见汽车数量作为规模目标。

默认采用自动调整的挂牌租金，玩家暂不逐户定价或指定租客；将来可加统一补贴、租金政策和税率。家庭预算按住房和就业方案共同评估。首版每户一名求职者，其他成员以人数记录；数据关系支持以后多名劳动者。暂不实现生育、教育、继承、购房贷款、房屋产权交易及企业完整资产负债表。

## 数据模型

- BuildingDefinition：建筑类型、占地、建设费、日维护费、住房套数、每套空间、容纳人数、基础私密性、参考租金。采用可调配置，不把数值散落在模拟代码里。
- BuildingState：稳定 ID、定义 ID、位置、朝向、道路入口、建造/可用/停用状态；住宅和工作场所附加数据分别存放。
- HousingUnit：稳定住房单元 ID、所属建筑、空间、人数上限和租约引用。公寓一栋有多套，不能只用整栋“已入住”布尔值。
- Household：稳定 ID、成员数、劳动者引用、储蓄、当前住房、稳定偏好、搜索冷却、上次搬家时间和决策记录。
- Resident：所属家庭、技能、雇佣合同、工作时间和出行计划。首版每户一名劳动者；家庭收入从雇佣合同汇总，不随机重新生成“收入阶层”。
- JobOffer / Employment：所属工作场所、薪资、技能条件、空缺/录用状态、居民引用。一个岗位只能雇佣一人。
- Lease：住房单元、家庭、约定租金、起止日、续约条件和欠租；挂牌租金与现有合同租金分开。
- DecisionRecord：候选方案、不可行原因、预算、通勤、各项得分、最终选择，供 UI 与回归测试使用。

住房/岗位容量是权威数据；入住率、人口、就业率等均为派生统计。所有关系使用稳定 ID，拆除后不复用编号。

## 两种住宅与建设

小别墅占地较大，只提供一套住房，最多一个家庭，空间和私密性较好。公寓占地更紧凑，首版暂定八套，每套最多一个家庭，单户空间较小、共享空间更多。具体占地和价格通过配置调平衡，不能把“别墅”直接定义为高收入专属。

住宅建成后即具备实际容量，但初始为空置。没有住户也扣维护费。住宅不因入住自动变为另一种建筑；以后扩建需要显式建设决策。公寓即使住满也不等于超员：区分单户人均空间、整栋入住密度和街区环境，不能混成一个“拥挤”数值。

玩家选择住宅类型并在道路旁放置，施工预览显示占地、容量、建设成本、维护和当前挂牌租金。预计收入必须注明满租假设，不能当成保证收入。

## 家庭如何选择

每户拥有相对独立、长期稳定的偏好：空间需求、私密性/拥挤厌恶、通勤时间价值、储蓄目标、环境需求和搬迁阻力。收入影响支付能力，不直接指定住房类型。偏好随机种子入档，不能每天重新抽取人格。

先判断可行，再比较效用：

1. 住房可入住、有空位、人数不超过上限；岗位有空缺且技能符合。
2. 家与工作地点有可行道路路线。无路不是一个很大的通勤数字，而是明确的不可达状态。
3. 储蓄能支付搬迁费用；预算考虑工资、租金、基本生活费、通勤支出和目标储蓄。储蓄可短期填补缺口，但不能永久让入不敷出的方案可持续。
4. 新方案相对“维持现状”的收益必须覆盖搬迁/换工作成本。

效用比较使用归一化后的分项：空间与私密性收益 + 可支配结余/储蓄收益 + 环境收益 − 通勤时间损失 − 拥挤损失 − 变更成本。各分项贡献可展示。不同单位不能直接用“人民币 + 平方米 − 分钟”相加；结余和空间收益使用边际递减曲线，避免单项无限压倒其他条件。

家庭会比较：保持现状、只换工作、只搬家，以及少量“换工作并搬家”的组合。初次迁入先评估可行的住房和工作组合并暂留名额，双方提交成功才真正迁入，避免“没工作不租房、没房不找工作”的启动死锁。失业家庭可用储蓄过渡并继续搜索，不立刻消失。

首版使用有限候选集而非遍历全部住房×全部岗位：包含便宜、近工作、空间大等不同候选，不能只采最近住房而排除愿意远通勤的家庭。候选规模和抽样种子可配置。

租赁与雇佣采用分阶段申请、预留、统一提交；同一空房和岗位不能被多个家庭同时占用。冲突使用固定种子的公平轮换裁决，不按数组最小编号永远优先。失败者保留当前住房/工作，不先释放旧合同再碰运气。

## 变化的节奏

正常家庭每隔若干模拟日错峰重新评估。道路变化标记受影响的通勤估计，分批更新；不会让全城同一帧重新搬家。失业、失去住房、长期断路和续租是优先评估事件。

第一版建议短期租约、最短居住期、搬迁支出和收益改善阈值。失去住房等紧急事件可以绕过冷却，但不能绕过房屋与岗位容量。道路短暂断开不会直接删除居民或把人口统计清零；家庭先进入通勤受阻状态，再按持续时间决定换工作或迁出。

新家庭来自有上限的外部申请池，携带稳定偏好、技能和初始储蓄。只有获得可行居住方案并成功提交后才计入本城人口。无可行住房、长期失业或负担过高会抑制迁入、促成迁出。城外选择作为候选，城市不能靠无限生成强制入住者消灭空置。

## 租金与资金流

挂牌租金按近期有效申请和持续空置缓慢调整，设每次变化上限、平滑窗口和合理价格范围。申请必须来自真实、有支付能力的家庭；同一家庭的多次候选评估不重复计作需求。房屋满租且无人申请，不能仅凭“满了”不断提价。

现有租约在期限内锁定，挂牌变化影响新租约与续约。续约前家庭会重新检查负担能力。修路只改变可达性和通勤成本，不直接给房屋涨价：家庭申请变化后，租金才逐步反应。

日结顺序固定：记录已完成期间的工资资格 → 发放工资 → 扣生活/通勤支出 → 按租约收租 → 处理欠租和储蓄 → 扣城市维护 → 执行下一期间的市场申请和合同变更。新合同不追溯产生此前收入。租金只转账一次，家庭扣多少、城市收到多少；未收到账的欠租不当作现金收入。

首版工资由工作场所的简化经营账户支付，外部销售作为明确的资金来源；企业停用或无雇佣不能空发工资。先不建设完整企业经营系统，明确这是开放经济近似，不能声称已有闭合产业链。家庭基础生活支出作为外部消费出口；接入现有商店购物时必须改为同一笔支出，不能重复扣款。

住宅原来的等级税收取消，租金成为城市核心经营收入。商工原有自动税收也停止与新收入双重叠加；后续税收应有实际经营活动作为计税依据。

## 时间、通勤与车辆

当前“2.5 秒一天”和独立交通时钟不适合工资、租约和通勤。引入单一模拟时钟，统一日结、决策冷却和出行计划；1× 每日时长可配置，初始建议约两分钟。暂停与倍速作用于同一个时间源，掉帧不能漏结算。

第一版决策使用道路最短路线的预计通勤时间，包括住宅/工作场所接入距离；游戏地图尺度到游戏分钟有明确配置，UI 显示同一口径的时间。暂不宣称包含真实拥堵。后续加入平滑拥堵成本时，寻路与家庭评价使用同一版本成本。

所有居民的雇佣和逻辑通勤均被模拟，可见汽车可抽样显示。现有 48 个上限目前限制的是任务本身，必须拆开，不能因第 49 辆车没有显示而失去工资或无法就业。采样车辆不能单独决定工资到账，也不能把抽样车流当成全体拥堵反馈。

保留道路、跟车和货运代码的可复用部分；通勤任务的来源改为明确的居民和雇主。逻辑出行绑定出发时的起终点，期间搬家或换工作不令车辆瞬移；在安全阶段结束/重规划，下一次出行使用新合同。

## 玩家必须看得懂的反馈

- 家庭面板：成员、雇主、收入、租金负担、储蓄、通勤、主要偏好，以及最近一次选择的主要原因。
- 建筑面板：总套数/已出租/空置、挂牌租金与实际租约收入、维护、净收益、申请数、租不出去的主要原因。
- 就业面板：岗位容量、已雇佣、薪资和招聘失败原因。
- 城市面板：实际人口/家庭数、迁入迁出、空置率、就业率、平均通勤及分布、实际收租和维护。
- 道路建设反馈：列出通勤明显改善的家庭数量和后续迁入变化；不把道路变化后的所有市场变化都直接归因于该道路。

第一版无需聊天式居民 AI；结构化偏好、选择记录和少量可读文案足以让玩家理解原因。

## 实现顺序

1. 完成并验证沿路建筑基础：不同尺寸地块、入口、旋转预览、碰撞及 JSON。保留已有建筑位置与道路。把纯模拟测试和 Unity 运行时验证补齐。
2. 增加建筑定义、住房单元、家庭、岗位和合同；替换人口/岗位统计，接上两类实际建造住宅；先固定租金，验证空置和容量。
3. 加入预算、求职、住房联合评价、名额预留和错峰决策；实现迁入、搬迁、失业和迁出。保留可重放决策记录。
4. 接入统一时钟、真实租金转账、维护、欠租和自动挂牌调整；实现修路影响通勤再影响选择的完整循环。
5. 接通居民出行与车辆展示，完成家庭/建筑/财政 UI、旧存档迁移和长期回归。

上述步骤共同构成第一版，不以“先生成一些家庭数据”作为完成标准。先测固定租金是为了验证选择模型，再加入动态租金定位反馈问题。

## 存档和测试

升级到新存档版本，保存实体 ID、合同、储蓄、偏好、随机状态、日结标记和待处理申请。旧存档从真实拥有的建筑生成兼容住房与合成家庭；旧版没有个人历史，必须标明是初始化，不能伪称恢复了历史居民。旧小占地公寓可保留兼容定义，不能扩大模型挤占邻居。保留道路、城市资金、日期、建筑位置和货运库存；旧代表性通勤在迁移时安全清理并由新就业关系重建，避免重复出行。迁移先对副本校验并备份原档。

至少验收以下场景：

- 高收入、高储蓄偏好的家庭能选择公寓；普通收入、厌恶拥挤的家庭在预算可行时能选择远处别墅。
- 不修改偏好和收入，只缩短道路通勤，部分家庭改变选择；修改种子前后结果可复现。
- 空房不能产生人口和租金；满房不能超租；一个岗位不能双重雇佣。
- 家庭租金支出与财政实收一一对应；空置仍扣维护，读取或重复汇总不再次收费。
- 供需没有变化时不发生全城每日搬迁或租金单边失控。
- 断路、失业、拆房、搬迁途中和资金不足有明确状态，不凭空删除家庭或瞬移车辆。
- 把可见车辆上限改小，不改变家庭收入、岗位分配和入住结果。
- 存档恢复后，合同、偏好、储蓄、待处理搬迁及后续决策保持一致。
- 连续模拟至少一年并记录总人口、空置、租金、欠租、迁出和财政趋势；先证明模型可解释且稳定，再扩大城市规模。
