# 道路新内核第一批验收（2026-10-14）

基线：110c4ea，保存在 `codex/baseline-road-core-20261014`；实现分支：`codex/road-core-20261014`。主分支、远程历史、用户原存档和Profiler原文件未改动。本批是架构切片，不增加《都市：天际线》的玩法完成百分比。

## 已接管的真实调用链

普通SampleScene/Editor/Player自动入口现在是HarborCityRoadCoreGame。建路 → World持有独立NetworkData → 派生Lane/Connection共享Geometry → 堆Dijkstra生成Drivable ID路线 → 固定步快照跟车/意图/预约/提交 → 实车交货及现金结算 → 新格式保存读取。运行入口不实例化CityTraffic，不调用旧Move、逻辑路线展开或旧Dijkstra回退。

- Junction有持久ID；PhysicalRoad有专用ID、两个端点、方向、速度和xyz中心线。1001个几何样本的直路仍只有两个拓扑顶点、一段车道路线。
- Lane ID预留32个车道索引/方向，当前只实现每方向一条；Road ID上限33,554,431。Connection由入/出车道组合标识，字典保留混合long哈希。多车道运行尚未实现，预留ID不等于完成车道功能。
- Vehicle的正常位置只有route/cursor/distance（有向几何首点起算的世界距离、车身中心）。不写旧segment/progress/RoadNode。静态几何、路线、路口连接不在每车每步重建。
- 每Drivable占用排序后读取相邻前车；所有跟车读步初快照，意图按车辆ID协调，再统一提交。高频复杂度O(N + Σk log k + N log N)，后者为明确的仲裁排序；不再逐车扫全城。少量入口查询只读目标桶尾车。
- 保守整路口预约覆盖进入前/离开后的安全区；等待点离连接中心最多2单位（短车道按长度/3）。纯连续分裂不是冲突路口。未知信号/换道/行人语义未假装实现。
- 拆分保留前段Road ID，分配后段和新节点，保持端部切线、迁移正反向距离/路线。整批验证位置和引用后提交。拆掉驶过的道路会裁剪无用历史；当前/未来路断开则任务明确中断，货物和世界位置保留，现存路面上的中断车继续占用空间。
- 新增连接造成安全区已有多个占用者时，施工明确拒绝且不部分修改，等待驶离可重试。这是第一批限制，尚未实现施工等待队列及任意车流下的连续编辑迁移。
- 库存发车时扣除；目标有空间和现金才交付，款项一进一出；成功一次后任务从热集合压缩退休，保留库存/现金/交付账目。没有装饰货物或宏观刷数。
- 新文件 `harbor-road-core-v1.hcrc`：显式魔数、版本、原始double、SHA256校验，保存道路/身份分配器、任务、库存、现金、时钟与固定步余量；原子替换和备份。拒绝旧城市JSON/其他格式，不迁移、不覆盖原 `harbor-city.json`。

## 暂时没有接管 / 保留源码的原因

这是一个可交互的新内核运行切片，**当前重构分支还不能按原完整城市玩法游玩**。新仓库闭环尚非原工厂/居民运输接口。居民、经济、市政、分区、建筑内部入口、原UI、货车返程、服务任务、行人、换道、信号、道路升级/反向/撤销、桥隧工具均尚未接回。基础工具支持两点施工、端点吸附、显式样本拆分/拆路，不自动识别内部交叉；几何可以有高程和曲线，不等于桥隧施工工具已迁移。

旧HarborCityGame自动启动代码已删除，新入口有独立生命周期。旧CityRoads/CityTraffic及业务源码暂留供后续逐条调用链移植和保留模块回归，**没有新引擎失败后切回旧引擎的产品开关**。本批没有宣称全局删掉全部历史包袱；原逻辑拓扑包装、旧存档迁移器/等价路径测试仍在未接入的模块里，下批逐项替代并删除，不作为新内核验收约束。完整可运行基线通过Git切回，不能把新入口的缺失能力当作永久玩法删减。

## 可重复验证

1. `Tools/VerifyRoadCore.ps1`：501个模型断言；有向可达、堆搜索网格、采样密度、正反向/曲线/高程/连接中位置迁移、当前/历史道路拆除、施工失败原子性、跟车/路口预约、库存资金守恒、结算一次、存档校验/继续运行及调用方DTO隔离。另有1000/3000活动车安全检查、12轮编辑检查。
2. `Tools/Verify.ps1`：保留模块全套回归通过（车道/路口/行人/运输/居民/市政/存档等）。这些运行旧模块，不代表它们已经在新入口集成通过；未删断言或放宽旧断言伪装迁移成功。
3. `Tools/RunRoadCoreNative.ps1`：隔离项目编译普通SampleScene并运行新默认入口，实车发货、活动中拆分、位置一致、保存后逐步继续、实际到达结算。不会修改用户当前场景。
4. `Tools/RunRoadCoreNative.ps1 -Window`：可见Development Player，1440×900、60FPS上限、vSync关闭，每种1000/3000车分散/排队 ×1/3倍，3秒预热、6秒记录。检查活动数不变，单调真实时钟供给固定步，不通过deltaTime截断掩盖丢步。截图确认实际画面；后台黑图不作为渲染证据。
5. 交互：进入Play，点击“发货 A→B”，观察源库存-1、车在曲线和连接上前进、到达后目标库存+1和现金转移；行驶中“拆分第一路中点”无跳位置；拆路后车辆保持中断；保存/读取可继续。WASD移动、两点修路、Esc取消。

Profiler依次展开 `City.Simulation → City.RoadCore.Step → Occupancy / IntentAndReservations / CommitAndSettlement`；车辆表现单独在 `City.RoadCore.Views`。不启用Deep Profile，Marker均为静态。

## 性能结论的范围

原始轻量结果见 [本批基准](Benchmarks/2026-10-14-RoadCore/README.md)。当前简化核心3000车完整模型步约1ms，窗口约60FPS/实际接近1和3倍；窗口仍约16–68KB/帧分配，GUI是后续需归因的部分，不能据此声称“零GC”。由于没有旧居民/市政/完整交通语义，**不能与原固定城市7–8ms/步作等价配对、不能宣称十倍性能收益或完整城市性能达标**。原城市导入后的新模型对照、全业务规模、长期压力、内存/预览预算尚未完成。
