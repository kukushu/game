## 数据结构和正确性依据

`CityDepotJunctionRouting` 由 World 唯一持有，是 Network 的可丢弃派生缓存。共享图遍历实际 LaneConnection，按“路口 ID + 完全相同的合法出口车道 ID 集合”合并入口车道。集合精确比较，哈希碰撞不会合并不同集合；状态、出口、种子均按稳定顺序生成。

合并正确性的理由：同组任意实际进入车道允许的后续出口完全一样，所以树的每一步均可用真实 `Network.ConnectionId` 拼接；到达下一状态的实际车道也属于该状态。缓存不假定任意转弯，不创建 U 型连接。共享图只保存状态映射、出口与逆邻接，不复制道路几何或拥有可编辑拓扑。

每场按需最多两棵 BFS 树，双侧合法入口作为稳定排序的多源/多目标种子。每状态一个 `int` 前驱/下一状态与一个 `long` 真实车道，共 12 字节/树；不保存每建筑完整路线，不保存行驶时间标签。BFS 优化状态连接层数，**不是最短时间路径**，建筑候选采用第一条合法者，因此完整建筑间路线也不保证最少段数。

- 去程：直接同车道向前可达则直接停靠；否则按目标 RoadAccess 的两侧合法车道，查其上游转向状态，找到首个已达状态，恢复父链并接入准确入口。若缓存主路已先经过目标车道，立即在第一次合法位置停靠，避免再绕回目标。
- 返程：车辆实际 lane/distance 不变，先处理同车道直接到达；否则走完当前车道，由其转向状态查反向 BFS 的下一跳，沿真实连接前进到选定垃圾场入口。下一跳层数下降，重建另有节点数上限保护。
- 去程通、返程不通时如实返回不可达；原 `PrepareServiceReturn` 在扣除建筑垃圾前检查，未伪造返程。正常实测未遇不可达。
- 原发车占用、路口预约、准入/续程事务、移动/变道、安全距离、任务与垃圾交接全部保留。仅 Service 路线生成可选进入 C；居民、普通货运、垃圾积压优先级、派发频率、车队/载重/处理容量、财政和保存格式未改。

大图 **7128 状态 / 14248 车道**，约减半；小图 **170 / 170**，没有压缩。纯 Junction 一个状态不能保证转向合法，最坏仍需要每入口车道一个状态。C 没有复用 B 的加权车道树实现，也没有声称所有路网都能压缩。

共享图一次构建约 O(L+C+出口排序)，每场建树 O(S+E′)，两棵树 O(S) 内存；请求 O(局部候选数+输出路径长度)。原重复 Dijkstra 约 O((L+C)log L)/搜索，B 每场至多四棵加权树。C 构图仍扫描全网，但同 Network 只做一次，不在每建筑请求时搜索全图。

## 失效、验证和边界

Network 身份变化时整份共享图及各场树失效：包括增删、拆分、重连、升级、方向与速度变化；目前对纯速度修改也保守重建。基地自身 lane/distance/use 变化只清该场；建筑版本变化时从现有 Waste 的活跃场列表移除已删除/退役关联，退役任务可回原路处理。普通车辆移动、预约、时钟、无关建筑入口变化不使树失效。缓存不入 `.hcity`。

实际通过：

- **23287** 专项断言：双向/单向/多车道、四岔、连续道路车道索引转向限制、路中及边界入口、同车道前后、对侧入口、去程通但返程不通、孤岛、增删/拆分/升级/反向、入口变化、确定性、基地生命周期和预算回退。使用 Network.ValidateRoute 和准确端点独立检查，不比较最短成本。
