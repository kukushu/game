# 两类商品经济失衡：证据与归因（2026-11-05）

结论：不是单一“居民没钱”或“食物生产不足”。已确认存在一项错误开店判定，同时购物资格/营业班次互相限制，企业的工资与商品毛利又缺少足够余量。企业现金耗尽后，营业和进货条件形成停摆循环。不能只靠增加启动资金解释或解决。

本次只诊断，不改运行时源码、商品价格、工资、税率、正常初始资本或玩家存档。基线9d1b158。主证据来自复现原小城的40000个0.05秒模型步（约16.67个模拟日），不是大城Player的新经营验收。

## 1. 错误开店：没有供应商记录，被误当作没有可达店

投资代码直接以Consumption.UnservedDemand决定开店，但该集合含“家庭尚未完成供应商选择”的需要。Request又要先找到空闲成年人，才搜索门店；因此家庭成员都在工作时，尚未做可达性判断的需要也会被拿去开店。

独立道路查询得到以下规划时事实（不是根据新店后来失败倒推）：

|Tick|模拟日|目标住宅|规划前已有店|其中可达店|其中有现金的可达店|
|---:|---:|---:|---:|---:|---:|
|10441|5|9|1|1|1|
|10801|5|9|2|2|2|
|13321|6|11|3|3|3|

违反了“无可达店才开店，有店缺货先补货”的批准规则。最终7家店中，#20、27、31、36、40五家没有任何顾客、成交或采购，合计10000外部启动资本全部变成8775工资和1225税。这是明确的实现问题。

仅在Temp编译副本中补“已有可达店则不再开新店”的诊断对照，商店数从7降至1，但该店仍在第7天现金耗尽。这个缺陷确实制造额外开店，却不是全部失衡的唯一原因。对照人口同时从88变45，不能用总成交28对85评价方案优劣。未将该临时修改写入正式源码。

证据：[investment.csv](investment.csv)、[FinalLedgers.csv](FinalLedgers.csv)。源码：CityBusinessInvestment.cs第38行、CityCoreConsumption.Request先检查空闲成员后AssignSupplier。

## 2. 有钱、有货、有需要，但家庭与商店的可用时间冲突

家庭#1的两名健康成年人都在商店#14上班。第6天两个直接观测点：

|时间|家庭现金|缺食物份数|在家可采购成年人|店内食物|店内实际付薪员工|
|---|---:|---:|---:|---:|---:|
|14:24|1098|9|0（两人均在本店上班）|21|4|
|21:36|1098|9|2|21|0|

在营业时间没人能从家出发买东西；回家后店已不满足营业条件。21:36时商店仍有103元，不是先破产才出现这次冲突。家庭#2也出现相同现象。不能据此断言所有家庭全天完全无法购物，但已经证明正常采购受到实际班次与资格的限制。

规则链：Request要求成年成员“不在岗、无任务、位于家中”；Open要求商店当前有实际付薪员工，BeginVisit到店时再次检查Open。商业员工统一采用11:00起、8小时、最多1小时错峰的一组班次，没有第二班覆盖。工业员工的班次不同，所以仍观察到了实际购买，而不是交易模块完全失效。

证据：[AvailabilityExamples.csv](AvailabilityExamples.csv)、[ShopExamples.csv](ShopExamples.csv)、[visits.csv](visits.csv)。源码：CityCoreConsumption.cs第132—153行、CityEmploymentDesign.cs、CityCoreConsumption.BeginVisit。具体由时间冲突、通勤、运输入场分别损失多少成交，尚未用单因素实验量化；不能把全部销售不足只归于这一项。

## 3. 现金收支已经对不上，且部分工厂理想状态也亏

两家实际成交过的店，最终现金账可逐项核对：

|商店|启动资本|零售收入|已付工资|税|采购预付|最终现金|剩余食物|
|---|---:|---:|---:|---:|---:|---:|---:|
|14|2000|260|1534|171|555|0|24|
|22|2000|1440|1712|228|1500|0|28|

两店分别只卖13、72份食物；每份零售20、批发15，已售商品毛利只有65、360，远小于工资加税1705、1940。剩余库存也占用了现金，不能把全部采购支出误称已实现亏损；但营业规模、成交速度和成本显然没有形成可持续匹配。

这不仅是销售晚发生：#14每岗日薪143、4岗，满勤工资572/日，按当前占岗税约57/日。单靠每份5元食物毛利，需要约126份/日才能覆盖；开业时全城只有18人，首次现金耗尽时36人，且家庭还带有初始物资。当前投资只检查有人可招聘和有缺口，没有检查这种营业规模是否可行。

食品厂也有独立的成本问题。#34的岗位日薪163；一级厂每份食物需15工人分钟，8小时班次对应480分钟。即使原料充足、没有任何等待，每份成本至少为：

`原料8 + 加工2 + 工资163 × 15 / 480 = 15.09375 > 批发价15`

尚未算税，理论满负荷也不盈利。#16、25、34实际到岗劳动转为加工的比例仅约61.3%、58.7%、67.2%；工资按到岗时长先付，之后才检查原料/仓储/加工条件，闲置会进一步压低余量。#16实际每生产一份的已付工资约6.42，已经高于扣掉原料和加工后的5元毛利。

#16最终现金核对：`1200 + 销售4350 - 原料2624 - 工资1952 - 加工608 - 税366 = 0`。原料采购包含未消耗库存，这首先是现金流证据，不能直接当作会计利润。工资、税、工作量和价格之间的取舍属于需要审查的规则/参数组合，不应通过临时免费劳动或额外注资掩盖。

证据：[FinalLedgers.csv](FinalLedgers.csv)、[FirstCashZero.csv](FirstCashZero.csv)、[jobs.csv](jobs.csv)。源码：CityProductionSystem先PayAttendance再ProcessFactoryWork；CityCorePayroll按实际到岗结算；CityProducts定义15元批发和15分钟劳动；CityCoreFinance按占岗数收税。

## 4. 现金归零后，库存和需求无法自行恢复交易

第17天：88人、家庭合计36193元，最低一户仍有435元；企业现金合计0。商店仍持有52份食物、工厂43份，均有道路和完整基础供给。27户显示no_stock，但库存并非全部为空。

此时“现金0→付不了工资→没有满足Open的员工→顾客到店也不能买→没有零售收入”，且本地批发须由商店预付。Tick21036发生了一个直接例子：顾客到#22，店内有28份食物、道路与供给完整，但现金/付薪员工均为0，成交0。

全程实际生产820份食物，其中640份出口，居民只买85份；家庭累计未满足食物422份。外销有外部买方付款，本地商店却因前述条件不能承接交易，所以“先给本地物流机会”并不等于本地需要得到保障。这是资金与营业问题通过物流放大的结果，不能只说总产能不够。

工厂回款后也持续按原料目标24补货，没有独立运营现金保留；最终#16、34各有24原料、14/15食物却现金0。出口要求库存至少16，本地商店又无钱预付，残余存货不能自动变现。工厂初次现金0后曾有在途销售回款，并非第一次归零就永久停止；这里说的是40000步末尾已无活动运输的最终状态。

证据：[summary.csv](summary.csv)、[families.csv](families.csv)、[visits.csv](visits.csv)、[FinalLedgers.csv](FinalLedgers.csv)。源码：CityCoreConsumption.Open/BeginVisit、CityCoreIndustryBusiness.Depart、CityCoreTrade原料补货与出口阈值。

## 5. 日用品零成交需要更正解释

初始日用品按14天目标带入，低于2天才补购。早期3000人Player窗口结束于Tick25983（约10.83个模拟日），本来尚未到最早补购阶段；零成交本身不异常。

长周期小城首次日用品需要出现于Tick31801，第14天06:00:36。此时承担实际需求的#14、22均现金0、无付薪员工；#14分配到7份日用品需要，但无力采购。另两家仍有现金的新店#36、40，分配到的两类需求均为0。工厂投资又会跳过没有批发支付能力的需求门店，因此日用品链没有启动。既有压力夹具可成交1份，只能证明交易通路存在。

所以应把“初始物资尚未消耗到补购阈值”和“补购时供应链已停摆”分开，而不是把任何日用品0成交都当成系统错误。证据：[FirstDailyNeedMarket.csv](FirstDailyNeedMarket.csv)。

## 验证边界与建议顺序

- 无供水预算切换、原12000/15000步50%/100%预算切换两种输入，均复现88人、食物成交85、未满足422、企业现金0；预算切换不是崩溃的必要条件，不代表真正断供没有影响。
- 所有观测城市完成session.Validate；10家企业现金账误差均小于1e-5。增加独立可达查询和家庭观测后，最终保存SHA256仍为31d4df8e73c7296113dbcce190fa0e1526eef5d7256c1e4a6f47ef0aa2cfe8ee，与无这些附加观测的基线相同。观察没有改变业务结果。
- 运行入口：`Tools/DiagnoseTwoGoodsEconomy.ps1 -Results Temp/<新目录>`；预算对照加`-WaterBudgetControl`。原始CSV、首次现金0与最终存档留在Temp/TwoGoodsDiagnosis-20261105；本目录只保留轻量关键证据。错误命名的water-cut目录是未传开关的重复基线，不作为预算对照，实际对照是water-cut-input。
- 优先纠正“供应商未知≠没有可达店”的实现错误；再审查购物可用时段和实际营业覆盖，让家庭需要能形成交易。随后核对投资规模、岗位工资、商品毛利及流动资金，尤其排除正常一级厂投产就必亏的组合。
- 原因提示应区分无库存、闭店/无付薪员工、无空闲采购成员和无钱，避免把现金停摆误显示为缺工/缺货。
- 本轮未将任何候选修复写入运行时，也未对大城重做经营归因。不能承诺修正一个点就能使所有城市长期健康经营。
