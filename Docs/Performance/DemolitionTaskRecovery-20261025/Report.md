## 处理范围和行为

`RoadEditPlan.demolition`仅由`RemoveRoad()`传入。事务在原Network里存在、在候选Network中消失的**当前Drivable**，才将相应车辆置为`AwaitingRestart`。包括删除相关道路导致当前LaneConnection消失；也包括原来已经Stranded、这次又真的被删去当前有效路面的车。

只丢失未来路线、入口关闭、建筑不可用、撤销建路等其他中断仍走原Stranded/原地恢复逻辑。旧存档中已经Stranded且路面早已缺失的车辆，没有可靠删除原因，**不追溯猜测，也不批量套用新处置**。

AwaitingRestart是保留车辆与原任务身份的离路等待状态，不是合法道路上的障碍。位置字段保留最后位置供审计；该状态不参与车道占用、路口预约或活动车辆计数，也不在旧位置画一辆悬空的车。居民仍绑定同一个tripId，不会凭空到家、上班或发起第二次出行；观察文字显示等待重新出发。任务和货物并未被隐藏或删除。

| 业务 | 处置 |
|---|---|
| 普通货运，包括材料/商品与对外运输 | 原TripTask、Shipment、货量、种类、价格、ID、departedAt全部保留；从原origin合法入口重新规划与入场。**不再执行Depart，不再扣库存或付款**。最终仍按原到达结算。 |
| 居民Work/Home/Shopping | 保留原出行任务和citizenId，回家携带的商品继续由原Shipment唯一持有；从原出发入口重新入场，不重新消费、扣钱或改居民目的地。 |
| 垃圾车Pickup | 从原mission.pickup收取`min(载重, 当前积压)`，计入collected，并直接入原station.stored；完成并移除该任务与车辆/mission，归还车队名额。不新建驾驶返程任务。 |
| 垃圾车Return | 只将现有垃圾Shipment入原station.stored，清零载货、完成任务并归还车队；不再从建筑收第二次，不再寻返程路线。 |

货运/居民使用与正常派发**同一个PrepareDeparture和IndexDeparture**：原入口权限、方向、路线、源占用、间距和路口预约检查均保留。按原车辆顺序依次准入，成功一辆即登记占用，后面的车辆不能重叠出发。重试只发生在固定tick的整秒（每20个0.05秒步），不保存另一个计时器，冷热恢复时序一致；无队列时直接返回，不增加每步全车辆扫描。

原出发地、目标入口或道路不通时，继续保留任务等待，不能制造合法入口；重新接路后自动重试。垃圾场容量检查仍保留，容量不足也保留mission和载货等待，不能丢弃或超储。垃圾生成、处理速度、车队规模、载重、正常派发频率/目标优先级不变。

## 具体改动

- `CityRoadCoreEdit.cs`、`CityRoadCoreWorld.cs`：显式删除事务原因；候选与真实提交使用相同标记；新增离路状态、重新准入和受限的服务任务完成入口；后续道路编辑不把离路任务当道路占用。
- `CitySimulation.cs`、`CityCoreWaste.cs`：在原固定步边界先处理上述垃圾例外和待重发任务，继续原模拟循环。垃圾只使用既有mission、building库存、Shipment和总账。
- `CityRoadCoreSave.cs`：现有status字段读回新枚举，并保留冻结位置；没有增加存档迁移或旧格式适配。新版本能保存、读取和继续运行待重发状态；旧程序不能理解新增状态，不保证能读取此类新存档。
- `HarborCityVehicleViews.cs`、`CityCoreResidents.cs`、`CityCoreObservation.cs`：准确显示离路等待，不把最后位置当实际道路上的车；原任务仍可查询。
