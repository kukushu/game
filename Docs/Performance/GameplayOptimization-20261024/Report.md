## 阶段二：解除64MiB字节硬上限

用户本轮追加明确要求“放开64M限制”。最终实现删除ByteLimit及字节预算准入/淘汰条件，仍保留128基地数量上限、实际活跃设施清理、Network/入口正确失效和原算法回退。不是修改50倍时间/固定步预算。ReservedTreeBytes只作四树最坏驻留估算：每Lane为4×(double+int+int)=64字节，加每基地1KiB对象头/Entry预留；共享图和临时搜索堆不属于该数组估算，不能当作整个进程RAM上限。

取消硬上限前先测了纠正预算记账的控制版（仍有64MiB门槛），实际19.52×/53.45FPS/最大274.94ms。取消硬上限最终版19.83×/53.39FPS/最大270.41ms；本城96个基地在纠正估算后已经能够全部驻留，因此不能把二者很小的差异宣称成取消限制的独立加速收益。相对旧80字节保守预算版本，缓存反复淘汰已消除。
