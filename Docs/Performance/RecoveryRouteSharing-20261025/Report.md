## 17次查询实际是什么

复用同一真实玩家城检查点：SHA256 `0110347D2BC4E40E8CD98E841EE92F62D675935D076A21AE58D7F7A5A9ADB6CD`，tick642633、536辆车、删除道路87。不是重造三万/五万人城市，也不是最新F52现场。

在真实Unity Player仅对Temp源码加观察器，记录车辆、起点车道/精确位置、目标入口、双方可达方向、路线、节点展开序列和连接检查次数。诊断输出不作正式计时成绩。

| 观察项 | 结果 |
|---|---:|
| 恢复尝试 | 132 |
| FromLane / Dijkstra | 17 / 17 |
| 成功找到路线，最终恢复Active | 17 |
| 精确起点位置＋目标等完整查询键 | 17个，零重复 |
| 不同起点车道 | 13 |
| 业务种类 | 11返家、4货运、2服务车 |
| 累计展开 / 不同被展开车道 | 30942 / 9423 |
| 候选连接检查 / 合法边遍历 | 238886 / 176980 |

因此，本例不是“先搜了一堆注定失败的路线”。普通完整路径缓存没有直接命中；同车道不同位置不能直接当同一查询。同目标也存在停靠距离/方向差异。若共享整个最短路径树，还需证明源位置偏移、浮点加法顺序和等成本选择一致，不能用近似路径通过完整状态对照。

已有连通性预检查也不能消除本例的搜索，因为17条都可达；为此额外冷建SCC可能只增加工作。上述方向本轮不强行实施。

## 两阶段实验

### 第一阶段：减少重复字典查找

旧RouteToEither对每个候选先`Contains(link)`，合法后又两次`Get(link)`分别读Geometry.Length和Speed。按本例计数，连接字典调用为238886＋2×176980＝592846次。

先用一次TryGetValue取得相同连接对象，成本表达式和邻接顺序保持原样。三次原生观察的Dijkstra中位36.08ms、批量恢复42.13ms，改善有限且与其他阶段波动重叠，未以此宣布解决。保存这些样本后继续检查可共享的静态工作。

### 第二阶段：按需共享合法连接对象列表

17次搜索中有21519次重复车道展开。改为由当前不可变Network独占一个派生邻接缓存：

1. 某车道第一次被展开，按原`outgoing`顺序查权威连接字典，只保存实际存在的LaneConnection对象引用。
2. 后续搜索直接遍历同一有序列表；出发位置、目标入口、候选成本、父节点、队列和最终路径仍每次独立计算。
3. 不缓存整条路径或车辆/建筑状态，不复制权威连接规则，不预计算全网，也不在Network.Rebuild里搬入这段耗时。

本例产生9423个邻接条目、保存53782条连接引用。30942次邻接查询中命中21519次（69.5%，**这是邻接列表命中率，不是路径命中率**）。实际连接字典查询238886→72642；另有30942次邻接缓存查询。原始合法边遍历176980次、节点展开30942次及其顺序全部不变。

这仍是逐车Dijkstra。只是将合法连接筛选从每次搜索重复执行，改为每个实际展开车道按需做一次。`Route(int,int)`、标量MinimumTravelSeconds及垃圾场路径树未改；FromLane/普通建筑路径所共用的RouteToEither获得相同加速，不改变其业务调用规则。

### 所有权与失效

缓存是Network私有的只读投影，值为已有连接对象引用，私有调用者不修改列表。条目数最多为本Network的车道数，存储随其车道/连接规模增长，不按车辆、建筑对或查询次数无限增长。

道路新增/删除/拆分/方向/车道数/速度改变会创建新Network，缓存自然为空。入口重绑复用相同Network时，拓扑未变，继续复用；每次仍读取新RoadAccess和精确位置。普通车辆移动、任务、占用、预约和时间不使静态邻接失效，也不因命中跳过任何实时安全检查。缓存不序列化，冷读档从空缓存开始。

该实现依赖现有Network构造后拓扑不可变的约定。未来若引入原地修改连接，必须同步维护失效，不能默许旧缓存继续使用。

### 内存代价

该施工帧多分配约2198768 bytes（约2.20MB），不是GC优化。原生Mono的线程分配API无效，细分CSV保持-1；使用raw Profiler观察Dijkstra分配：旧1268334、新3467046 bytes，增量约2.20MB。旧raw复用上一轮同源码/存档记录，其CPU波动很大，**不将raw的90.07→31.42ms当作正式性能成绩**。

新增内存主要用于Network内的字典、列表和引用数组。未单独实测长期堆驻留字节，不能把分配量称为精确常驻量。9423条目/53782引用给出本例缓存规模；没有为每车或每目标建整棵树。旧Network不再被持有时缓存随它回收，本轮未做长时间连续编辑内存压力验收。

## 剩余结论

17次独立路径需求没有消失，当前结果不能证明可以安全减少到一次搜索。减少的是重复静态图筛选；成本/父节点/队列仍按原规则独立执行。也没有使用建筑对旧路径替代车辆当前位置路线，或在删除道路后借用失效旧树。

当前相同场景的施工帧仍约125ms，Network.Rebuild、全局Shape和分区几何等热点未动。没有修改加载、时间预算、模拟内容或实际车辆数量。建议这项小范围共享优化进入独立评审，普通游玩和更多冷查询负载仍需后续验收；本轮不合并、不继续其他优化。
