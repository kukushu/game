## 实际实现

每个基地最多四棵树：主入口/合法对侧入口各有去程、返程树，分别按首次需要懒构建。分开两个方向便于保留明确的入口距离和选择顺序，不为每栋建筑保存整条路线。

- **去程**：复用Network原堆，在权威有向Lane/LaneConnection图上做完整Dijkstra。每个Lane保存到车道末端的耗时、前驱索引和确定性的settle序号。起点种子仅计基地入口到本车道末端的距离；查询建筑中段入口时，从目标车道的合法前驱计入连接成本和末段部分车道成本，再恢复路线。
- **返程**：反向索引只从Network现有合法连接派生。目标种子为目标车道起点至基地入口的部分成本；反向松弛计入前一车道全长和真实连接成本。车辆查询时使用当前有向车道剩余距离，恢复实际前进方向的下一跳，车不会倒行。同车道直接到达另行处理；入口在身后时必须走合法回路。
- 路径恢复保留连接ID，原发车位置占用、路口预约、到达检查、任务与垃圾转移提交全部照常执行。返程路线第一条Lane及起始距离必须与车辆实际位置相同。
- 一个World拥有一个有界LRU；Network仅拥有可重建的只读图索引。每树是`double distance[] + int hop[] + int rank[]`，不入`.hcity`。
- Network对象变化即失效，覆盖增删路、方向、车道、速度和拆分。基地入口lane/distance/use/valid变化会失效；普通车辆移动、预约、时钟和无关建筑入口新增不会清空树。Waste沿原建筑revision/设施列表更新有效基地集合，删除基地的关联被清理；退役或不可缓存的基地走旧逻辑。缓存不可用时回退；可用树判定无路时仍按原规则拒绝，不跳过安全约束。
- 上限128基地，同时按`80×Lane数+256`字节/基地作保守数组预算，最多64MiB。该预算**不是整个托管堆的精确上限**；共享图、对象头、临时堆和诊断另计。

旧方案每个未缓存查询约`O((V访问+E访问)logV)`，会在目标附近提前结束。新方案每个基地/路网epoch最多四次`O((V+E)logV)`，查询主要是邻接检查和`O(路径长度)`恢复，保存约`O(4V)`/基地。超预算反复淘汰时，这个摊销优势消失。

后编辑测试确实向有在途车辆的World新增了独立道路，使Network身份变化；检查原有请求的成本/可达性后计树重建。施工事务、显示和首次SCC等其他派发检查不在这张“寻路批次”表里，未宣称测了真实点击编辑后的完整Player首帧。升级/反向/删除等更多拓扑组合由小图自动测试覆盖，繁忙路口受影响车辆的完整编辑矩阵尚未补全。

Unity Development归因的逐次调用数、展开节点、均值、P95/P99在 `routing-summary.csv`。最终窗口中单棵去程树最大约23.40ms、返程树27.27ms，单次垃圾服务查询最大44.37ms。完整步不可中断，仍可能超过8ms预算。不同墙钟窗口推进量不同，不能将其中旧239次与新355次请求总时间直接当成相同工作量加速比。

## 正确性：通过项与失败项

**通过的范围：**

- 9701项小图检查：双向/单行、多车道、连接合法性、同车道前后方及端点、中段入口、不可达分量、拆分/升级/方向/删除后的重算、入口距离变化、设施增删、LRU边界、无效位置回退。返回路线起始Lane/距离与实际输入一致，查询不改世界快照。
- 两城各4000步，逐步车辆间距和垃圾守恒、定期全城Validate；结果与不插入这些断言的新方案运行逐字节相同。均未发生安全断言失败。101项原调度预算/事务/在途恢复检查通过。

- 冻结4ac850c的核心另行编译，4000步终态与实验关闭组逐字节相同；基线没有被替换成另一套逻辑。
