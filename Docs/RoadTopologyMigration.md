# 道路表示迁移：第二、第三阶段的分批实施

2026-10-13，用户已授权继续第二、第三阶段。基线为 883756f；每次迁移一个明确的子系统，仍以完整交通状态、实际运行和配对性能决定是否继续。

## 顺序与技术约束

1. **第二阶段第一批：道路与车道静态查询。** 正常 Editor/Player 的 CanTravel、Kind、EdgeLength、SpeedFactor、EdgeWidth、LaneCount、LaneOffset 读取版本化逻辑道路快照。几何 span 保留原长度及方向。旧邻接顺序、Dijkstra、cost 累加顺序、车辆短边游标及路口算法暂不变。不能把几何分段减少直接算作交通拓扑已完成压缩。
2. **第二阶段后续：逻辑路线与寻路。** 先建立每条既有路线的 Road+距离区间视图，明确中途建筑入口、环路和同一路重复经过；再迁移搜索。压缩 Dijkstra 若只累加整个 corridor 的 cost 会改变 float 累加及平价路径选择，必须解决并对照，不能悄悄替换。车辆持久 ID/位置最后迁移，兼容存档字段只作边界适配；不能同时改变预约和逐车更新。
3. **第三阶段第一批：共享几何与私有施工草稿。** RoadView 读取道路中心线的原方向采样和纵断面，保留横坡、标线与桥隧规则；保持原 Mesh 顺序便于逐顶点比较。曲线施工先消除每个短段重复深拷贝整个网络，使用每次预览独占的一份草稿，失败直接丢弃、提交仍原子替换。此方案仍会扫描/重建邻接，不能声称已经是局部增量施工。
4. **之后：持久逻辑道路及编辑迁移。** 当前 RoadId=min edge ID 只属于快照；中途建路/拆路后必须通过旧边与距离映射建立身份迁移。需要专用 ID、分裂/合并区间、建筑入口偏移和存档版本。它与旧几何点删除、真正让车辆跨采样点不换交通道路有关，不能仅搬几行字段就宣布完成。

本轮不改变交通固定步、更新顺序、数量、车速、安全距离、行人优先、预约和居民/物流规则。道路键混合哈希继续默认启用。

## 查询迁移的所有权、失效与回退

CityRoads.nodes/edges 仍是施工和存档的唯一持久真相。CityRoadTopology 是从它派生的只读快照；正常游戏现在会调用它，Changed 和更换实例失效，Copy 不继承。查询间不重新构建。热属性查询只读取需要的字段，不返回完整几何结构体；RoadTraversal 用于需要几何的低频读取。

无直接边的 EdgeLength 仍按旧节点间距离计算，Kind/SpeedFactor/EdgeWidth 缺失时保持旧默认值；非法方向的车道数仍为零，LaneOffset 不因方向合法性丢失原数值。方向及可步行性保留。宏 CITY_ROAD_TOPOLOGY_QUERIES_DISABLED 可单独回退静态查询；既有 CITY_ROAD_KEY_HASH_DISABLED 也选择旧查询与旧哈希，保留原性能回退语义。存档格式不变，当前快照 ID 不写入居民/车辆存档。

## 验证方法与未完成边界

- 静态查询以原 RoadEdge 字段、原 SpatialLength 和道路类型函数作独立 oracle，覆盖两个方向、车道偏移、高程、稀疏 ID、动态编辑和加载；不能用已迁移查询验证自己。
- `Tools/CompareRoadMigrationReplay.ps1` 分别编译同一源码的旧查询/新查询，核对固定城市每一步完整存档状态（40预热+300正式步）。性能计时不包含状态序列化。
- 原生基准仍采用保存好的前后 Player、相同城市/配置，9轮2700步、子模块Calls/GC/最终状态对照。测量期间不运行另一份回归或编译任务；并发负载记录不作为最终证据。
- 普通 SampleScene 构建/独立运行分别验证施工、车道、路口、行人、物流、服务及原生存档。共享渲染需额外对照旧渲染 Mesh 和横坡，不把仅存在“Road surface”当作新旧渲染等价。
- 真正的 Road 级寻路、持久 Road ID、逻辑 distance 作为车辆唯一位置、LaneLink、道路编辑事务以及几何采样彻底退出交通拓扑，仍须后续独立完成。已迁移查询不能冒充这些目标已全部完成。
