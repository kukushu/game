# 道路与交通新内核（2026-10-14）

本约定取代RoadTopologyMigration中“旧存档兼容、旧路径选择、逐步状态完全相同”的约束。基线110c4ea保留在codex/baseline-road-core-20261014；工作分支codex/road-core-20261014。回退依靠Git，不保留运行时双引擎开关。

## 唯一事实与派生数据

- Junction：持久ID和xyz，仅真正连接/端点是拓扑顶点。
- PhysicalRoad：专用单调ID、起终Junction、方向、速度及多点中心线。点不是RoadNode，也没有寻路身份；端部切线属于共享几何，保证拆分后车道偏移连续。
- Lane/Connection：从道路生成的有向可行驶几何。Lane ID由Road ID和方向定义，Connection ID由入/出Lane ID唯一组合，不使用默认long哈希。几何和累计长度属于模拟内核，渲染只读取它。
- Vehicle：路线为Drivable ID序列，位置为路线游标与distance（世界单位，起点是有向几何首点，参考点是车身中心）。悬空/断路时使用明确的Stranded位置状态，不同时维护可写progress/节点游标。geometry采样数量不会增加路线长度。
- FreightDepot：真实库存、容量和现金；发车扣库存，到达并可卸货后一次性交付/支付。没有用装饰车辆或宏观计数代替运输。
- 邻近索引、邻接、连接几何、道路Mesh是派生数据；保存事实，读取后重建索引。新内核存档独立版本1，明确拒绝旧城市JSON/二进制，不删除或覆盖旧harbor-city.json。

## 第一批端到端与边界

交互运行入口使用新内核：建路/接线→拓扑寻路→车道/路口连接上的距离推进→仓库交付及现金结算→保存读取。先只支持基础道路及单行、仓库运输和保守路口互斥；暂无公交、真实行人、换道、交通灯、四车道/高速、地形桥隧工程工具和完整城市业务UI。这些是暂未接入，不是永久删除玩法。旧模块暂留供业务接口移植，但新入口不调用旧CityTraffic/Move，也没有失败时切回旧引擎。

固定步0.05模拟秒；先构建每Drivable按distance排序的占用，再读快照计算意图、协调入口/路口、统一提交。全步全车执行，carry跨结构剩余距离，不丢步；中心间距=车长1+最小间隙0.5。信号/换道/行人另批接入，本批不伪称复现旧行为。采用保守整路口互斥（入口与出口有空间才能进入），后续用连接冲突图细化。

道路拆分保留第一段Road ID，第二段分配新ID；保持原几何切线并按车道距离区间迁移路线/当前位置。拆除当前路面会保留货物/车辆为Stranded，不能传送到最近路。建筑入口使用Junction ID；内部入口和完整沿路分区接入随后单独实现。

## 预算与批次

目标为当前城市以及1000/3000真实活动机动车，60FPS、1×/3×；这是验证目标，不是保证。索引成本O(N+Σk log k)，稳定ID仲裁排序另有O(N log N)；前车查询只读同车道相邻项，入口/路口只读局部占用。分散与汇流拥堵分别测量，记录活动数/均值/P95/P99/GC/实际时间推进。修路重建是冷路径，单独计时；不拿模型基准当游戏FPS。

下一批依次接回城市运输任务/库存接口、内部建筑入口和分区施工、换道双车道占用/冲突连接、行人/信号/服务、完整城市存档和原UI。替代真实调用链后删除对应旧模块，避免长期维护旧字段适配。Jobs/Burst等在单线程预算与正确性明确后再决定。

参考CityFlow已阅读的Road/Drivable/Lane/LaneLink与阶段屏障思想；不移植二维几何、线程指针、shadow vehicle或其性能数字。历史研究证据保留，但不再作为等价性门槛。

源码依据：既有[固定版本对照](CityFlowTrafficDesign.md)，[roadnet.h 的 Drivable/Lane/LaneLink](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/roadnet/roadnet.h)，[engine.cpp 的 threadController / threadUpdateLocation / threadUpdateAction](https://github.com/cityflow-project/CityFlow/blob/81ee0f47659ca66177a71f81676691c58ee89184/src/engine/engine.cpp)。借鉴共享可行驶几何及读旧状态/提交阶段的职责；本批只有单线程稳定ID仲裁，未实现CityFlow的并行屏障与道路车辆链表，也没有借用其性能承诺。

第一批临时施工约束：纯连续拆分不互斥；真实连接处用进入前/离开后的等待安全区。新增路口若安全区已有多个车辆占用会明确拒绝且不提交，驶离后重试；后续再做施工排队与更细的连接冲突迁移。货车返程和编辑器热重载也尚未接回/验收。已实现与缺失见 [第一批验收](RoadCoreStage1.md)。

实现补充：存档采用魔数 HCRC + 版本1的二进制double，避免JSON数值解析损失固定步余量；已完成任务从热集合一次压缩退休，结算事实保留在库存、现金、delivered账目。Network实例更换及NetworkGeneration递增代表冷重建；编辑清理旧车道桶，避免历史道路永久增加每步扫描成本。拆分先验证整批路线与世界位置，再提交，失败不部分改写车辆。

## 2026-10-14 当前实现修订（取代以上第一批临时细节）

实际业务库存/财务属于原CityModel，工业会话通过ITransportBusiness扣货/交付，Depot只用于测试。World持有RoadAccess，保存Lane和纵向距离，不为每栋楼制造Junction。工厂原居民/岗位实际劳动仍参与生产，原居民通勤和市政尚未迁移。

RoadEditPlan统一新建/拆分/拆除：准备候选网络与车/入口迁移，活跃状态变化使计划失效，完整候选状态和安全校验通过后才修改真实事实。任意中心线切点插入共享rightVectors，保持车道形状和长度；该截面不是渲染私有数据。默认建设工具自动中途吸附和同高交叉，0.25高度容差以上的立交不连通。重叠施工拒绝，不能静默生成双份路。

核心当前格式4，城市封装2；保存自己的完整事实，旧版本明确拒绝，原文件保留。冷编辑仍完整复制与重建（3000车拆分均值约5.34ms、3.05MB），待测后再做增量方案。新默认窗口仍未恢复旧完整城市UI/地形/服务，不能把这些旧模块测试通过说成已迁移。
