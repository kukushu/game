# 建筑模型重构验证

验证环境：Unity 6000.6.3f1，当前格式 8 实体模型。

`Tools/Verify.ps1` 全部通过，共 306 项检查，另包含连续 365 天逐日状态、住房容量和现金守恒验证：

| 套件 | 检查数 |
|---|---:|
| 实体架构、ID、存档、拆除 | 42 |
| 自由道路与曲路 | 29 |
| 建筑放置、碰撞与接入 | 46 |
| 家庭与全年模拟 | 9 |
| 交通生命周期 | 7 |
| 居民实际通勤 | 28 |
| 居民岗位关系 | 15 |
| 实际工业生产 | 24 |
| 工厂现金流与工资守恒 | 54 |
| 确定性城市分析 | 40 |
| 原始结构化日志 | 12 |

全部运行脚本和编辑器检查脚本分别使用 Unity 自带编译器及项目引用编译通过。

Unity 原生测试在独立临时验证项目中实际执行，采用相同模拟源代码和编辑器检查，使用 Unity 自身 `JsonUtility`，四组全部通过：

- 六种具体子类、公寓/别墅 payload、成品/商业库存、入口、稀疏 ID 和 pose 往返。
- 自主迁入、岗位、实际通勤、日账目、存档续算、住宅拆除后往返。
- 真实货运任务、交付收入、库存、存档续算、工厂拆除与工资核对。
- 原有曲道路网、连续子类预览、建筑 yaw 和道路接入往返。

测试过程中修正了两个问题：长期 float 劳动累计误差改用 double 计数；JsonUtility 将 null 嵌套对象写成默认对象的问题改用显式空/单元素 payload 数组。原生比较对 double 允许小于 1e-8 的绝对误差，其他保存字段要求相等，并单独校验关系和现金守恒。

本次没有操作主游戏的 Play 画面进行点击、镜头和视觉验收。F3、建筑观察与建造脚本已完成类型/ID 改造并编译；实际画面、地形贴合和交互仍可通过项目菜单及 Play 检查。
