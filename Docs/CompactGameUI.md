# 分类游戏界面

底部仅保留六个分类按钮，进入城市时不展开。点击分类打开最多420×300的可滚动面板：

- 道路：普通修路、单双向与车道设置、方格路网、道路编辑/拓宽/拆除。
- 分区：住宅、商业、工业、清除，沿用框选/点选设置。
- 水电设施：电站、供水、排污、垃圾设施、手工管线及设施旋转。
- 对外贸易：连接、进出口定位、贸易与仓库数据。
- 城市观察：问题列表、财政、岗位、项目与模拟待处理时间。
- 游戏：保存、读取、临时无限资金。

右上角实时读取真实居民实体数、活动车辆数、资金与模拟时钟；暂停、1×、3×、20×、50×仍走原0.05秒完整固定步。目标倍率旁显示当前实际倍率：已完成模拟秒数 / 真实经过秒数，约半秒刷新，包含正常显示、施工和长帧经过的时间；切倍率重新采样，首个采样完成前显示省略号，暂停显示0。积压的请求时间不会算成已推进时间，也不会丢弃。

50×沿用32步/8ms预算（60FPS下需平均16.67步/帧），不强制大城跑满50倍。85项预算检查含20×/50×相同请求输入的完整保存逐字节对照通过；未实测50×真实Player表现。

右上角另显示电力和用水的“需求 / 实供”，使用游戏内部负荷单位，不冒称MW或立方米。现有模型住宅按实际入住人数、商业/工业按实际就业人数（乘2）、各含最低基础负荷计算；电力另含公共设施负荷，用水需求按原规则仅计分区建筑。实供来自原AllocateUtility的实际成功分配，同一建筑跨管网只计一次；原power/water仍是可用容量，不作为实供。CityModel在原分配循环维护只读派生总数，HUD不逐帧扫描全城、不触发额外刷新、不另设供应事实或修改规则/存档。状态栏增高48像素，建筑/道路详情同步下移。

后续按用户反馈补充第三项“容量”：HUD现在显示“需求 / 实供 / 容量”，第三项直接读取现有power/water有效设施容量（受预算、道路入口和水设施供电影响），不以实供或建筑总数代替。不连通的区域仍各自分配，因此全市容量有余也可能局部缺供；容量是负荷单位，不是城市可容纳人口上限。这次只改表现读取与中英文案，复用原HUD绘制与资源检查。
