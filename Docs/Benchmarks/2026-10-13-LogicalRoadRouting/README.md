# 第二阶段寻路批次

## 正常游戏的数据流

CityRoads.FindPath保留原512项单起终点缓存、输入、返回独立节点List和失效契约。缓存未命中时默认调用独立 CityLogicalRoadRouter：搜索队列只包含逻辑Road边界及调用者起终点（建筑可在内部），沿RoadCenterline遍历几何样本累加原TravelCost，再展开原node IDs供当前车辆使用。几何样本不再逐个进入新Dijkstra队列。

复杂度改善是减少优先队列/距离/前驱容器中的采样顶点；不是完全跳过样本。仍逐段累加成本，不能把整Road总成本一次加到路径上：IEEE单精度舍入会改变结果。显式FloatBits栈结构保留原队列逐样本存储的32位边界，无转换数组分配。单行、可步行性、环路、控制/类型边界和内部起终点均读取同一版本快照。

等价成本竞争的原发现顺序依赖被省略的几何节点。实验曾出现同成本不同路线；该方案未采用。正式方案遇到等价竞争或非严格递增浮点成本就回退保留的原Dijkstra，从而维持原选择。CITY_ROAD_ROUTING_LEGACY可整体关闭新寻路；旧哈希回退也直接使用原搜索。Profiler可展开 City.Traffic.Route.Search → City.Roads.Route.Logical，发生回退时同级出现 City.Roads.Route.LegacyFallback。

## 正确性

- 7512组精确路线序列对照，含对称等价网、多起终点、几何内部端点、曲线/高程、单行、环路、列表重排、修改/拆除、存档；2116次保守回退，其余用新算法。没有把“同样可到达”当作同一路线。
- 同一源码分别编译旧/新搜索，固定城市340步完整存档状态逐项相同；全量模型回归和旧寻路回退通过。
- 原生2700步各步任务、九轮最终状态、主要模块Calls一致；普通SampleScene构建/独立运行全部通过，含真实建拆、连续曲线、桥隧、车道、路口/行人、物流/服务及原生存档。
- 校验原始保存几何时先检查原节点间长度，避免派生构建把非法零长度道路变成异常；零长度/空stopFrom列表必须按旧契约Valid=false。新增模型检查覆盖这一防线。

## 尚未迁移

车辆仍使用展开后的旧route/segment/progress、同一逐车即时提交、跟车索引和路口预约。RoadId仍属于快照，不写入存档。本批没有完成持久Road实体、vehicle RoadId+LaneIndex+Distance、道路编辑区间迁移或去除几何点数据库。这些是后续独立批次，不应把压缩搜索当作整套道路架构已经完成。
