# 运行卡顿诊断

## 2026-10-11 本批证据

用户确认不操作也卡。用户真实 Unity Profiler 的一帧为 CPU 30.32 ms、HarborCityGame.Update 22.91 ms、Self 19.32 ms、GC Alloc 1.1 MB、GC.Collect 3.04 ms。单帧不能代表平均帧率；Self 包括尚无独立采样标记的普通 C# 子调用，不等于 Update 中某一行独占这些时间。当前证据证明模拟/展示主循环和分配需要优化，尚不足以排除渲染或编辑器的额外开销。

诊断读取已有 harbor-city.json 副本（第 85 日，174 栋建筑、364 条图边、120 个出行），不覆盖存档、不更换用户当前城市。这个存档不是用户当前第 114 日城市的实时快照。通过同一 Mono、同一诊断脚本和同一输入比较提交 91f5426 与本批模型；先预热派生缓存和 JIT，然后采样。

| 测量 | 优化前 | 优化后 |
| --- | --- | --- |
| 每个交通固定步平均耗时（模拟 50 ms，241 步含预热） | 20.817 ms | 15.607 ms |
| 每个固定步平均分配 | 1,260,423 B | 500,233 B |
| 全部出行位置/朝向兼容几何 API，每轮平均分配 | 162,624 B | 13,440 B |
| 分析展示快照平均耗时/分配 | 3.170 ms / 1,035,044 B | 2.998 ms / 1,035,044 B |

CPU 时间会随机器负载波动；副本诊断不含 Unity 渲染、输入、组件调用与编辑器，因此不能声称真实帧率已经达到某个数字。分析快照仍有约 1 MB/次的分配，尚未优化；它约每 0.25 秒更新，不是每一帧必然执行。交通内部仍存在遍历和服务调度尖峰，不宣称已消除全部卡顿。

证据文件：Temp/PerformanceBefore.log、Temp/PerformanceAfter.log。两份执行完毕的模型 JSON（PerformanceBeforeState.json / PerformanceAfterState.json）SHA256 相同，出行、工资、服务、随机状态与经济账目一致。测试输出不提交临时大文件。

## 已修正的重复工作

- 跟车检查将本车近距离路线几何移到其他车辆遍历之外，保留原距离、车道占用及最小安全推进结果。
- Ground/Underground 改用道路已有派生缓存，同向/反向都能查到，结构编辑后重新建立；兼容同一节点对的结构掩码。
- 单起点/单终点寻路缓存真实道路结果，按道路 revision 失效，步行与车辆分开。缓存上限 512，返回独立可修改列表；不缓存车辆阻塞/预约、不改变路线算法与同成本顺序，不存档。
- 距离与路面采样直接计算数值，不为投影点创建含停车牌列表的 RoadNode。
- 车辆几何中间点改为值类型，保留原 Corner/Position 兼容入口。Unity 车辆显示调用 PositionValue，不创建临时图实体；1,000 次重复值类型采样的纯模型分配为 0。
- 复用车辆展示的 ID 集、过期列表、空闲队列；缓存 Renderer，只在显示状态、材质或名称真正改变时更新。实际返程/步行/接人变化仍更新名称。居民出行不设新的显示上限。

不改变模拟步长、模拟速度、交通优先规则、居民任务或存档格式 34。不降低车辆数量，不通过消失、跳过出行或降低模拟精度提速。

## 在真实城市继续定位

正常录制 Unity CPU Profiler，展开 HarborCityGame.Update，再看以下标记的 Time ms 与 GC Alloc。无需仅为了看模块而开启昂贵的全量 Deep Profile。

| 标记 | 范围 |
| --- | --- |
| City.Simulation | 固定步模拟总耗时；一帧可能执行多个步 |
| City.Traffic.Movement | 车辆推进、选道和路口释放 |
| City.Traffic.Services | 学校、医疗、消防、警察、垃圾与交通观察 |
| City.Traffic.ResidentsAndIndustry | 工作、生产、购物及日结；包含周期性尖峰 |
| City.Traffic.Dispatch | 公共服务与货物派车 |
| City.VehicleViews | 车辆/行人展示、信号灯和选中路线 |
| City.AnalysisSnapshot | 周期分析快照与可选 Trace |
| City.RoadInput | 道路命中、吸附、预览及施工 |
| City.ServiceViews / City.DetailViews / City.BuildingProblems | 设施展示、定位详情与异常扫描 |

分别记录正常运行、暂停、取消道路预览、关闭详情后的多帧情况，保留城市规模、速度与帧耗时分布。日结帧与普通帧分开观察；暂停快而运行慢则重点看固定步，暂停仍慢则看展示、预览及编辑器/渲染。下一轮应以真实城市这些标记的耗时为依据，不继续凭类名猜瓶颈。

## 副本诊断命令

在项目根目录运行 `Tools/MeasurePerformance.ps1 -SavePath "城市存档的完整路径"`。脚本只在 Temp/PerformanceDiagnostic 编译纯模型并加载副本，不修改源存档。Tools/Diagnostics/PerformanceProbe.cs 不加入正常游戏，也不参与 Verify.ps1 的顶层测试编译。

全量模型回归包括 32 项缓存/结构编辑失效、方向与步行分离、缓存返回值隔离、容量淘汰、原生实体保存以及值类型几何零分配检查。已有转弯、实际货运、路口、行人、桥隧、市政及存档回归继续执行。
