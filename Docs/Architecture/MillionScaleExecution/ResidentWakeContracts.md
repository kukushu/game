# Resident request invalidation contract (MS-002)

Baseline: 93d97f2004b3893d3b76bf765e972e21405d19fa. This is an audit and a staged prerequisite, not activation of event-driven requests.

| Fact / lifecycle | Authoritative writes | Consumer / required invalidation |
|---|---|---|
| tripId | CityCoreResidents.Depart / Arrive; initialization, explicit public writes | AdvanceRequests first guard; both departure and return-to-zero invalidate the member |
| retryAt (float) | AdvanceRequests +0.25; CityCoreConsumption.Step +0.5; BeginVisit; public writes | Both earlier and later deadlines; preserve float rounding and all bits |
| visitUntil (double) | Depart(Home) clears; Consumption.BeginVisit sets arrival + VisitSeconds; public writes | Both earlier and later deadlines; preserve exact double value |
| owner binding | CityEntities constructor / AddResident; RemoveResident detaches | Deserialization/object initialization has no owner; listeners attach to the new session, never persist |
| membership | AddResident / RemoveResident; MoveResident preserves Members position | Separate structural invalidation required in MS-004, not a global building Revision subscription |

Repository-wide C# search found no ref/out accesses to these three resident facts and no GetField lookup of them. Other types have their own tripId and remain unchanged. CityCoreSave already explicitly supports [CitySavedFact] properties; ordinal wire name/type/order remain identical, private backing fields and the owner stay outside the save. No migration/version adapter is needed or added.

A setter must store the original value before notifying. Floating equality must not discard negative zero or NaN payload writes. Notifications only invalidate derived scheduling state; subscribers must not dispatch, settle, or evaluate incomplete departure/arrival transactions inside a setter. Candidate evaluation stays at the existing AdvanceRequests stage with original Members order. No per-person delegate/closure is necessary: the unique CityEntities owner exposes an internal observer for one member and fact kind.

Guard-only filtering cannot sleep an otherwise eligible member until a shift time: job assignment/release, employer funding, illness, ability, household changes, day and network/access dependencies still require MS-005..009. Until then they remain conservatively polled. Synchronous request/log callbacks and writes to later members during a pass require explicit order tests before activation. A successful shadow run without these contracts is not proof that arbitrary state changes are safe.

MS-003 acceptance: direct writes (including earlier deadlines), detach/new owner, actual dispatch/arrival/shopping, float/double bits, frozen-baseline wire and full-state replay. MS-004 must prove the earlier-deadline positive case and retain a deliberately bypassed-notification negative control. Runtime resident polling is unchanged in both stages.


MS-009 contract: CityCoreResidents.PlansInvalidated emits only internal derived-state invalidations at the existing request boundaries. Road NetworkGeneration, day and day-length changes invalidate all plans; new-access and endpoint-availability signals invalidate endpoint dependencies, including failed/missing/unreachable dependencies. Unknown revision coverage falls back globally. Callbacks must only mark derived state, never synchronously edit, dispatch or settle. Endpoint notification order is NOT actor execution order: consumers deduplicate affected actors and evaluate in authoritative Members.Ordinal order. RebindAccesses currently increments NetworkGeneration despite reusing Network and therefore conservatively invalidates globally. Last unsubscribe detaches World signals and clears pending endpoints; cold sessions seed current facts. Detailed audit, tests and limitations: [MS009-PlanInvalidation.md](MS009-PlanInvalidation.md). Production polling remains active pending MS010–013.


MS-010 follow-up: the direct public arrivedDay counterexample exposed a missed timed-return candidate. departureDay/arrivedDay and observedHome/observedWork/observedRevision/lastCommute now use the existing explicit saved-fact property mechanism, emitting internal TripDay or CommuteObservation invalidation after storing the fact. Their original wire names/types/float bits remain unchanged; cold/init writes without an owner emit nothing. Normal Depart/Arrive writes remain in their original order. The full shadow listens to these and MS003–009 signals; unproven early eligibility failures stay conservative. Development mode may change commercial shifts without changing funding qualification and therefore needs its own safe-boundary policy invalidation. Noncandidate oracle evaluations must not teach or repair the shadow. See [MS010 acceptance](MS010-FullShadow.md); real sparse execution remains gated by MS011–013.


MS-011 opt-in execution: CITY_RESIDENT_GUARD_SCHEDULE enables the unique CityCoreResidents-owned derived guard index. The ordinary build retains the original foreach. Only trip/retry/visit and proven household/death/at-home ability/attendance/today-departed prerequisites control candidate membership; original business guards are still rechecked. The primitive CityWakeQueue moved to Runtime and is reused by tools. Candidate links follow original Members slots, allow later synchronous wakes, and defer earlier wakes. Structural changes rebuild from facts; guard/state setters update local membership, and date changes wake only date-blocked members. Classify synchronizes a transient changed date before sampling it, covering change-date/write-departure-date/restore-date sequences. No routes, funding qualification or shift-time plans are cached by this index. Baseline a843016/native18 exact results and model maintenance-inclusive evidence: [MS011](MS011-GuardExecution.md). Default activation and Player gains remain gated by MS012–013.


MS-012 optional temporal execution: CITY_RESIDENT_TIME_SCHEDULE requires the guard flag. The SAME guard index consumes original effective departure/healthy-shift-end inputs only after an original no-request decision; minimum is tick+1. Expiry clears the plan and restores original business evaluation. Job/funding/all state notifications invalidate affected plans; MS009 endpoint dependency sets include missing/unreachable home/work/location, while topology/version uncertainty invalidates all live plans. Context changes (day/day length/development mode) invalidate; inconsistent manually edited dayElapsed/calendar disables temporal sleep until the unified clock agrees again. No new route query, dispatch rule, save fact or simulation timestep is introduced. Unsupported qualification categories conservatively poll. Model exact-state and maintenance-inclusive evidence: [MS012](MS012-TemporalExecution.md); real Player/default activation remains gated by MS013.
