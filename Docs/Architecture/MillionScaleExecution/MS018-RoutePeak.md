# MS-018：剩余购物峰值归因与车道对缓存实验

2026-11-01。冻结基线a2325d9；运行时只将Network.SharedRouteCapacity从4096提高到8192，仍使用原A*、确定性排序、精确入口距离、车辆准入与8MiB逻辑字节预算。不改居民/购物/营业/运输规则、时间或保存协议，不引入线程。候选源码为本报告提交中的Network及测试差异，实际二进制身份见CSV。

**这次是车道对缓存，不是此前128→256的垃圾场树容量，也不是4096项建筑对缓存。** 后两项没有在本轮改动。MS018仍IN_PROGRESS，家庭按需唤醒没有实施。

## 新峰值的真实组成

普通Release曾测得剩余帧1405ms。此次在相同原生Mono城市轨迹的tick13941进行固定步归因：Step1352.46ms，Consumption1322.35ms，Admission1291.34ms，RouteLookup1276.44ms，RouteSearch1216.14ms/9229次；Movement5.30ms，居民19.71ms。以上嵌套，不能相加。这是**原生Player固定步分项，不是无观察普通FPS成绩**；采样及回放没有替代正常帧验收。

[分项CSV](MS018-RoutePeak.csv)。逐帧/分项GC分配不可用，保持-1。旧CoreProfile的source_blocked字段没有完整埋点，不能将其0解释为没有被占用拒绝，也不能由查询数推算成功出车数。

复用QueryObserver只聚合13941的真实请求，无溢出：Blueprint29680次，其中Hit25649、Miss4031；4031次Materialized都属于不同建筑对，没有同一未命中建筑对重复构造。4026次的目的地为商店5206，结合消费层耗时说明主要流量，但目的地类型本身不是任务用途的独立证明。

[4031条实际未命中建筑对](MS018-RouteMisses.csv)、[权威入口及反向入口](MS018-RouteAccesses.csv)可独立核对。按原BothDirections规则展开主/反向入口，扣除3次同车道正向直接到达，得到16121次归一化车道对请求，只有7106个不同车道对。重复请求不等于全部重复搜索：现有4096缓存已复用一部分，但工作集超过容量，有进一步减少淘汰的机会。聚合CSV不保留完整LRU事件顺序，不能只凭这些集合推算准确命中数。

没有直接重构搜索工作区。额外只读分项探针中，清空queue/costs/parents/settled在14672次搜索里合计约13.15ms（.NET64）；其量级不足以解释秒级峰值。Mono x86第一次探针在后续保存对照中OOM，明确失败；64位重跑完成观察开关完整保存对照。没有将失败数据当通过，亦没有把.NET数字等同Unity帧时间。

## 修正之前缺少的原生状态对照

原生暖态tick13900完整保存SHA256为 `9a4869822fa936f737c124ac6734a2bac6bc74e52715b08364c9661496eb0c3b`。旧零售索引4096、新索引4096（热起点带观察/冷起点带观察）、新索引8192（冷起点不观察）均执行同样61步到13961，完整保存SHA256都为 `3f73656986a097a58543a92f4219b1e3cc1490575f2cd6183992d24bc6a50510`。每个完成的运行还通过20步热/冷继续模拟、完整校验及增量占用索引oracle。

第一轮全预热归因完成输出和上述校验后，退出停滞，480秒被监管终止；它不是正常退出PASS。随后从同一原生13900快照重试及冻结旧实现对照均退出0并匹配最终完整状态。后者用于补证，不把冷读重试的耗时替换首次全预热数据。

诊断工具只增加指定Tick的有界查询统计、入口导出、点路由计数、可配置基础预热步数（默认仍200）；固定步现在也在开始前正确应用路由选择参数。观察者在finally释放。结束后等待渲染边界再退出，不声称已查明或修复Unity退出停滞根因。

## 回归与界限

- .NET64/Mono各61168个合成查询、237492项检查通过，包括原Dijkstra最短成本/合法性、方向/多车道/边界/大坐标和缓存压力。其1074条A*/Dijkstra等成本路线差异是既有算法对照，不是本次容量改动引起；本次改动的完整状态对照严格相同。
- 增强测试：保留原长路径字节压力；再用10000个短车道对要求缓存达到8192并发生淘汰，独立验证条目上限，8MiB断言未放宽。
- 完整VerifyUnifiedRouting原历史回放因缺少 `Temp/RecoverySearch-20261025/native-after/window/pending.hcity` 未能运行。未删原测试，另选合成fixture/压力子集；不把子集称为全套通过。
- 核心回归23627、岗位10000、格网1522、分区83、水电460474通过。原生8192固定61步/冷热20与4096完整保存同。
- 30k普通Player各30秒单对，200步+8秒显示及200基地树预热在计时外。1×FPS59.80→59.86，倍率均约1×；50×目标实际3.186→3.226，FPS46.72→46.00、最长58.56→52.18ms。未见明显回退，但FPS约−1.5%，单对不足以证明小幅变化可靠；不宣称所有指标改善。
- 本改动降低一部分重复搜索，**约1.14秒仍是严重卡顿**，真实不同车道对的首次计算仍存在。健康经营、长期交通活性、十万人50×与整个MS018仍未验收；没有实现家庭按需调度，也没有引入另一个通用寻路系统。
