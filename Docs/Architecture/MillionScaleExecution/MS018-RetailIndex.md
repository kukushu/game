# MS-018第一阶段：零售索引不再扫描大片空桶

2026-11-01。依据[十万人十日调查](MS021-TenDays.md)，先修原MS018“营业店候选”中的实测热点；家庭按需唤醒尚未实现，不把本阶段当作全部MS018完成。冻结原实现为83ec624，运行时只修改CityRetailIndex。

## 改动及不变量

旧Collect以16单位网格穷举整个查询矩形，成本与查询范围面积成正比；城市只开放少数有货店时，远处家庭每次扩大半径仍查找大量空桶。tick13901/13941消费层约5.20/4.68秒，内部路线搜索只约0.69/0.68秒，不能先归咎于寻路。

索引现在记录**本轮非空桶的键**，Begin只清空上一轮非空桶。Collect比较矩形桶数量和本轮非空桶数量，选择较小集合；扫描非空桶时仍检查相同矩形边界，并使用原精确距离运算和原distance→shop.id排序。复杂度从O(矩形桶数+候选排序)降至O(min(矩形桶数,非空桶数)+候选排序)，附加O(本轮非空桶数)整数键。桶和候选仍引用唯一商店对象，不保存第二套库存/营业状态。

没有改家庭遍历、搜索半径序列、最近可达店规则、资金、库存、预付、派车、在途、营业和模拟时间；没有引入线程或改变存档格式。稀疏与密集路径通过同一个几何函数过滤，最终排序一致，不依赖非空桶插入顺序。
