# R3 可用性修复：真实界面验收

日期：2026-10-15。基线：`codex/road-core-20261014` 的 `b8f2a6f`。本批暂停新增城市玩法与架构推进，只修复现有交互与功能性画面。城市16/业务8/设计4/核心15格式不变。

## 真实复现与原因

在用户正在使用的 Unity 6000.6.3f1 / SampleScene / Game 视图实际操作，退出原运行后重新 Play，从资金65000、人口0、道路0的空城开始。使用 computer-use 的系统鼠标/键盘操作，不向界面注入 `MouseState`，不通过业务方法代替下述鼠标验收。

1. 点击“修路”后按钮变成“结束修路”，说明模式已进入。但 Update 用 `mouse.y > Screen.height - 410` 排除了屏幕上方整条横带，面板右侧空地也被拦截；相机滚轮还有独立300像素横带限制。
2. 在有效地图位置点击，`hasStart` 实际置为true，文字变为选择终点，但没有起点图形、鼠标道路预览。距起点不足4单位直接return，地形射线未命中也直接return，均无明确原因。
3. 点击终点后道路数量增加、资金扣除，证明 Raycast → PlanConnectedRoad → Commit 实际成功；原路面直接绘制贴地稀疏车道几何，分区是接近地面的水平薄盒，均被起伏/显示LOD的地面遮挡。面板透明、提示换行和内容超出固定区域又放大了“没有响应”的感受。
4. 真实放置设施发现水管与路面同色，长线只取两端高度，重合的水/电线不易分辨；设施方块也无法按用途辨认。
5. Editor 在 Play 中重新编译脚本会丢失未序列化的模拟对象，而旧视图仍留在场景，呈现地图可见、界面消失。**本批没有实现内存世界热重载**：缺少模拟时明确提示停止Play、重新播放并读取存档；正常验证先停止播放再编译，不静默创建另一座城市。已保存的城市文件保留。

基线截图：[空城](Results/R3Usability/Before-Empty.png)、[面板外点击被吞](Results/R3Usability/Before-BlockedClick.png)、[无起点标记](Results/R3Usability/Before-NoStartMarker.png)、[已扣款但路面破碎](Results/R3Usability/Before-RoadSurface.png)。

## 修复范围

- 输入命中使用与实际绘制一致的 `MenuBounds`，并合并财政/观察/道路编辑面板的真实矩形；不再拦截整条屏幕。相机与地图输入共享排除判断。
- 主面板不透明、宽度780以内，小窗口可滚动；修路/倍速/保存读取在前。模式、预览、操作结果有独立固定高度，文字改变不再把按钮推走。
- `HarborCityConstructionPreview` 只拥有起点环、道路/管线光标线与显示材质。道路输入变化时至多约每0.12真实秒重新准备只读方案、检查价格和建筑/项目冲突；指针静止且版本/资金/选项未变不反复准备。预览仍有复制/校验整个道路草案的冷路径成本，不宣称局部O(1)。
- 提交时重新生成并校验方案，不提交跨帧保留的旧草案。`CheckRoadPlacement` 复用已有几何占用判断，检查建筑及在建项目与资金；失败保持起点以便调整。短路、水面、未命中地形、入口失效、重复道路、资金不足及失效方案均提供反馈。已有内核少数英文异常在视图边界做有限适配，未来仍应逐步采用类型化原因。
- Esc 同时处理 InputSystem 与 IMGUI KeyDown，取消所有建设手势；换工具、读取清空旧起点/预览/选中。管线不再错误套用道路4单位最短长度，合法性由现有管网命令判定。
- `HarborCitySurfaceMesh` 根据共享道路几何生成显示细分及地表间隙，保持原采样折点，桥梁等离地几何保留原高程；不写道路或车辆位置。分区覆盖层贴地细分并留可辨网格缝。Terrain显示LOD误差收紧至0.5，不改地形高度事实。
- 建筑沿用稳定ID增量对象，简单用途颜色帮助辨认；未更换模型。管线沿地形采样，蓝色水管与黄色电线采用不同显示高度。所有这些只影响表现。

## 已完成的真实鼠标流程

Game视口约1510×810，Editor窗口约2034×1096（坐标仅作本次复现记录，其他分辨率按地标操作）：

1. 从空城点修路，在平坦中央偏南位置点击两端（本次约870,690与1300,690），再沿垂直方向点击两端（约1100,580与1100,810）。看到两条道路形成交叉口，拓扑道路4条、节点5个，资金按施工扣除。
2. 点住宅划区，在横路西侧北面刷一处；点工业划区，在东侧南面刷一处。看到绿色/黄色用途，随后真实成长住宅与工厂。
3. 点电站、供水站、排污口，分别在东侧横路北面建设（本次约1198/1238/1271,673）。均看到建筑、成功提示和扣款；不是预先生成的设施。
4. 用水管、电线的两次点击建设线路。供水/排污设施需要管线接近中心（现有规则约1单位）；只在道路中线铺管并不代表接上路旁设施。实际接到设施中心后供水/排污容量均为160。
5. 选择3×运行，经真实日界迁入3人、就业2人，看到黄色通勤车实际驶向路口。未修改居民/交通/生产算法或直接生成居民。此小城不代表完整物流经济或规模城市验收。
6. 点“保存”，点“读取”，观察道路、5座建筑、居民/岗位与时间恢复，继续运行。最终版再次重播，通过按钮读取同一鼠标建成的存档，蓝/黄色管线、用途颜色与网格清楚显示。
7. 在面板右侧、原来410像素横带内的地面点击，起点状态成功进入；Esc退出且下次施工不沿用起点。
8. 暂停、用保存按钮保存，尝试穿过供水站附近施工，出现红色预览且点击拒绝，再按保存。完整城市文件SHA256前后相同：`AA2728DE7B31DA23990351650E069979ED3457CF8D6460682EC52E0599684815`。这项对照来自真正界面操作。

## 自动检查与局限

- 23437城市检查、3218道路核心检查、10000岗位查询分配检查、6000步采样开关完整状态对照通过。新增预览不改变事实、重复预览、资金不足、失效草案、建筑冲突不修改完整保存的检查。
- Unity `CityUsabilityChecks.Run`：249项地表间隙、网格朝向、裁剪区间、离地道路不贴回地面、分区高度、预览只读和过期方案检查通过。它不代替鼠标验收。
- 原地形普通图形Player的Trading自动验证通过：真实消费/返家携货、工资、货运、财政、垃圾、动态道路与在途读档；这些由夹具命令准备城市，**不称为鼠标验收**。
- 老的 `-harbor-city-construction-validate` 在“commute/work/return loop”断言失败。专门构建基线b8f2a6f复验也在相同位置失败，未删除断言、改交通规则或伪报通过。记录见 [基线失败](Results/R3Usability/BaselineConstructionFailure.txt) 与 [本批失败](Results/R3Usability/CurrentConstructionFailure.txt)；该历史验收仍需单独归因。
- 当前未逐一真实鼠标验收所有坡地、水边、桥隧层、道路类型/转向组合和低分辨率；资金不足/过期方案的全状态断言由自动测试覆盖。桥隧视觉不回落有网格测试，但并未恢复桥隧施工工具。本批不宣称所有功能性画面问题消失。

## 性能记录与影响检查

[普通Player 1×/3×采样](Results/R3Usability/native-window.csv)：12居民、18建筑、11逻辑道路、活动峰值3辆（服务车3辆）。1×59.888FPS，实际倍率0.9981，P99帧17.980ms、32323B/帧；3×59.994FPS，实际倍率2.9997，P99帧16.996ms、42453B/帧。包含选路编辑面板，并非鼠标施工每帧的性能基准，不与旧批次不同负载直接宣称加速。最终三条错误翻译只在Editor显式Refresh编译/交互复核，采样代码与物理算法未因此改变。

本批涉及宿主输入/菜单、相机排除、显示预览/地表/建筑/管线、只读施工预检、本地化和诊断。施工预检是唯一必要领域变化，使用现有RoadEditPlan和占用规则；没有增加第二套道路、位置、库存或时间。预览、颜色、网格、材质和选中状态归视图，不进入存档。显示细分增加冷重建顶点与对象成本，未改模拟步/车辆数量/碰撞精度。区域和道路整批重建仍是明确过渡限制，本批没有借机扩展架构。

最后已显式Refresh确认Assembly-CSharp更新，再从空城启动、通过读取恢复鼠标建成城市，复验建筑入口冲突显示中文、Esc清除、暂停留城。Editor自动导入并非每次切换焦点都即时触发，验证前应核对已编译版本，不能仅看源文件已修改。

后续仍以可用性排查为先，新增城市功能与进一步架构重构保持暂停，等待用户另行指示。
