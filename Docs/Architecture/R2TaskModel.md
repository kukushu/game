# R2-A：任务、货物与路线的第一批实际分离

2026-10-14。用户授权重新审查 R2，按可工作的小批次实现，不能把以下过渡依赖称为最终架构。

## 选择与唯一事实

|对象|拥有事实|不拥有|
|---|---|---|
|TripTask|独立单调 ID、出发/目的建筑、Work/Home/Freight、居民 ID、出发时刻、生命周期、Shipment|车辆坐标、道路几何、建筑库存、工资|
|Shipment|剩余在途货物与单位价格；第一版身份由所属 Task ID 唯一确定|商店/工厂库存副本、复杂转运/企业合同|
|RoutePlan|车辆当前导航路径和终点站位；每车独立，不与缓存共享可写 List|居民身份、货物、几何采样|
|Vehicle|单调车辆 ID、唯一 Task 引用、导航 Plan、当前 cursor/distance、换道及中断物理状态|出行目的、居民 ID、货物数量、价格、出发建筑的复制字段|
|Network / Drivable|从 PhysicalRoad 派生的有向车道/连接及共享几何、允许连接、冲突|车辆/任务/业务账户|

实际根仍是 WorldData：tasks 和 vehicles 独立集合，tasksById / vehiclesByTask 为派生局部索引。车辆 Task 引用必须指向该集合中的同一对象，不是另一个相同 ID 的任务副本。车辆→任务关联只存一次（车辆存 Task ID，加载解析同一对象），任务不再存可独立修改的 vehicleId 反向事实。居民 tripId 在当前运行链引用 Task ID；Observe/Validate 经 FindTaskVehicle 派生关联查询。已测任务 #10001 对应车辆 #1，不能依靠数字碰巧相等。

本批暂为一任务一机动车；没有空闲车队、候车队列、公交乘客、多站任务或拆分货单。不为了未来可能性提前实现这些业务。World仍兼道路事务与任务准入协调；后续可以抽独立 TransportTaskStore/Coordinator，但不能通过另建集合复制当前任务。库存/家庭/居民仍由原城市事实拥有，物理移动不回调这些业务。

## 生命周期与真实调用链

CitySimulation.RequestCommute/RequestFreight → 原准入（可达性、路线、入口间距、预约、epoch）→ 候选 TripTask/Shipment/Vehicle/RoutePlan → 城市 Depart(TripTask) 关联居民或扣原库存 → CommitAdmission 同时登记任务、车辆和派生关联。

未准入不扣库存、不发布任务、不消耗 ID。交通每步照原顺序计算换道/意图/预约/全部物理提交，输出 TransportArrival（同时带 vehicle ID 与 task ID）。居民确认 task ID、货运按 task ID 记录销售；成功后 ACK 清 Shipment.remaining、标任务 Completed、车 Delivered，同边界退休两集合和索引。容量不足不完成，不丢货，下步重试；没有永久完成任务表或永久收据集合。

中断时任务保留 InTransit，车辆的 Stranded 状态表示当前承运受阻；不另复制一个可与车辆矛盾的“任务受阻位置”。道路事务候选验证/原位重映射只更新路线与物理状态，保留原任务对象/ID/人货；修复不会重新 Depart。死亡、换家庭、关闭企业等仍受 R1 生命周期约束；本批没有擅自增加撤离/改派玩法。

## 已删除的旧负担与过渡限制

Vehicle 的 origin/destination/purpose/citizenId/departedAt/cargo/price/route/arrivalDistance 字段已删除；不是保留旧字段再同步新类。业务 Depart 不接物理 Vehicle；物流在途货量读取独立 Tasks。旧类布局的夹具改为明确同时种入任务与实车，安全/钱货/动态施工断言未删除。

**物理位置仍通过 Plan.segments[cursor] 取得 Current，尚未独立。** RoutePlan 的存在不等于已经完成“物理位置不依赖路线”。这是下一批 R2-B 的主要目标：VehiclePosition(drivable, center-distance) 与导航未来段进度分开，事务定位由物理位置独立证明，不能保留两套可独立写入的位置。移动/连接入口出口需以统一提交函数维护导航一致性，环路重复车道不能只靠 FindIndex 推导进度。

LaneConnection 目前仍是 Drivable.IsConnection 的语义，没有独立类/真实端口。现有中心二次曲线与冲突图保持；独立连接 ID/进口出口/端口/共享几何的改造必须作为另一批，避免同批同时换任务、路径选择和转弯算法。动态施工依旧全量冷验证，并非已经完成局部编辑。

## 新保存

城市格式 8 / road-core 11。独立 nextTask、任务列表（含 Shipment）、车辆→Task ID、RoutePlan、物理状态、欠步/调度游标均保存。加载先读任务表，再解析车辆引用；重复、缺失、孤儿或多车占同任务均拒绝。加载后的引用指向同一事实，派生索引/可达性/候选索引重建。之前格式明确拒绝，不写迁移器，不删除用户文件；新默认文件名 v8/v11，原存档留在原处。

## 验证与性能

2141 城市断言和 2700 内核断言通过：真实从家通勤、到岗才生产/工资、真实返家、等待卸货不丢库存/资金、拆分/拆路/修复/升级/换道双占用、保存精确续跑。新增独立 Task ID、同对象身份、任务退休、孤儿/重复占用拒绝和旧格式清楚拒绝。Unity Mono Development Player 构建及默认城市原生实际行驶/货运/结算/在途编辑/精确存读/跨帧车辆 Transform 检查通过。
