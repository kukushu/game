# 十万人阶梯挑战：实际结果

## 批次1：有界逐条路线淘汰（2026-10-16）

基线b1bfa97。DispatchRoutes原4096条容量满后调用Reset，一并清空客运/货运蓝图。改为合计仍≤4096的侵入式LRU：命中只移动已有节点，满时仅移除一条最久未使用项；正/反向和客运/货运键不变，路径计算未改，车辆仍独占可编辑Plan。网络对象变化、入口编辑和施工仍整批失效，这是正确失效，不等于容量淘汰。

同一3000人初始保存、真实10日、相同有界宿主：完整初始/最终/在途继续保存哈希完全一致，候选、就业、钱货与垃圾结果未改变。

模块影响：仅DispatchRoutes和可选诊断计数；无业务字段、时钟、城市保存变化，无新增权威事实或业务依赖。LRU在普通游戏默认编译生效，不是benchmark特供；结构额外节点最多4096个，每次查询平均O(1)哈希/链表维护，实际路线数组仍有内存成本，不能宣称“缓存零内存”。

新增RunBoundedCityScenario管理既有Runner的进程树、时间/停滞/内存限制。普通/采样不并行。初次监督器因JSON数字键序列化失败，但子模拟正常结束；原资源CSV保留并明确恢复元数据（不虚构退出码）。已修复为字符串键，并验证600秒正常结束；另实测10秒期限安全结束自己子进程树。强停不保证内存状态保存，已有初始/在途文件和刷新日志保留。OS采样峰值为进程树观测，不等于城市净内存或瞬时峰值。

下一批：检查两种合法出发方向均已占用时的廉价预检；不能把“其中一边堵住”当作全部不可出发，也不能趁优化改选一条不同道路。之后修万人城支管并推进规模阶梯。


## 批次2：服务车辆出发前的方向与空间预检（2026-10-16）

垃圾服务可以使用建筑入口的两个方向。PrepareTransport在寻路前检查两侧真实占用，并用现有静态可达性判断哪些出发方向确实能到目标；只有所有可达出发方向均被堵住才提前拒绝。无路仍报告NoRoute；存在另一条空闲长路时仍执行原最佳路线选择，不趁优化改变派车规则。严格保留1.5间距边界、换道双车道占用、目标两个方向、单行和动态网络失效。Reachability本身有缓存和冷构造成本，并非免费。
