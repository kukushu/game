## 根因与结构选择

最差物流步 281,625 次请求中 280,875 不可达；单车道保存方向上，前面商店无法掉头到达。4096 项蓝图缓存反复全清，68/69 次，重复分配失败 Dijkstra。源站反压单独试验并未消除该问题，已经纠正最初假设。

新增 LaneReachability 是 Network 允许连接的派生有向图：不能用无向物理连通性，不能把同车道上游自动判为可达。该上游必须存在实际回到车道的环路。派车先做结构性筛除，再调用原路径/空间/预约检查；源站反压只拒绝同站位已有车的真实间距阻塞。商店顺序不变。

冷构建 O(L+C)，每个源车道闭包 O(L+C)，最多缓存 64 个源，不保存全部 OD 矩阵；路网实例更换全部失效。大量不同源冷查询仍可能昂贵，需要进一步实测 SCC/组件 DAG 等替代，而不是宣称大型城市已解决。物流仍有 F×S 候选枚举，筛除后 P99 仍约 54ms；下一批须直接减少不可能的候选迭代，而非继续缩小 Dijkstra。岗位 wrapper 的捕获变量探针实测 10000 次分配 160000 B，待独立修复，不能归给 Dictionary 本身。
