# R3-C2 真实购物、雇主工资与商业账户

本批是现有正常城市链的端到端接入，不是第二个交通引擎。固定时间驱动；所有账户、库存和出行在没有 Unity 场景时也工作。Unity 只加载作者资产和读取运行结果。

## 唯一事实与生命周期

- CommercialBuilding.Account 是商店现金唯一事实，保存冷 ShopAccountData；实际初始资本、零售收入、工资支出和批发预付各有明确账项。工厂仍拥有原 FactoryState，不复制库存。
- CityCorePayroll 只对实际到岗劳动从雇主现金扣款，Citizen.wageCredit 是已支付尚未转入家庭的工资，跨日按整数转到家庭，零头保留。原 factoryWageCredit/totalFactoryWagesPaid 改成通用 wageCredit/wagesPaid；不保留可写别名。人员移除保留已领取工资累计，退休建筑由 CityEntities 归档保存同一账本，不再保存第二份 retiredFactoryWages 聚合值。
- Household.openingSavings 是迁入自带钱；incomeReceived 和 retailPaid 是实际收入与购物支出累计。家庭钱 = 开局钱 + 实际收入 - 购物付款。不是政府收租。
- Shopping TripTask 是去店的实际乘车任务；到店且有实际工作人员/商品/供给才能买货。商品随后唯一属于居民 carriedGoods；开始 Home 任务后移交给价格为零的 Shipment，居民持货清零；真实到家后计入 ConsumptionState。车辆仍只负责物理与到达报告，不持商业账本。
- CityConsumptionState 只保存消费累计、付款累计和下次调度时间；门店空间桶与本步在岗人数都是派生索引。
- 城市14 / 核心15 / 业务6 / 设计2 保存以上事实和不可变配置；旧格式清楚拒绝，原存档未删除。

## 模块边界、事务与复杂度

生产阶段维护实际付薪在岗数；零售按配置周期建一次有库存且营业的空间桶，再从家庭位置扩圈查候选。使用结构可达性筛选，最终创建实际路线；没有为每个候选再寻一次完整路线。它选最近世界距离的可达门店，是明确近似，不声称原版精确购物选择。

出发先校验交通准入，再扣批发预付款/移交商品，物理到达后才收货/售货；失败不扣钱不丢任务。每日工资整批预检余额溢出再支付。守恒校验涵盖活跃/归档企业库存、任务载荷、居民携货、消费、出口；企业付薪等于个人已领/零头信用/已移除个人已领；批发托管等于到货成本加在途货款。

关闭有在途任务或现场居民的建筑现在明确拒绝，拒绝前后完整保存相同；空闲建筑可归档并保存。原因是目前端点仅有一个可用标志，不能在禁止进入时仍允许现场人员撤出。此限制避免人员/付款永久丢失，是暂时玩法缺口；以后实施撤离/关闭状态，而不是静默传送。

变更影响：经济新增工资/消费/门店账本；居民负责实际目的与携货；交通协议增加 Shopping 与 Home 商品载荷；保存必须增加事实；配置按 Employment/Retail/Production 分组。旧领域测试中工资字段名称同步修改，仍验证资金、交通、存档断言。没有往 World 增加企业算法，没有双份库存或视图反馈进模拟。CityModel 仍有旧公开字段；不宣称全工程边界已彻底收紧。

## 可调设计数据与已知近似

Assets/Resources/GameData/Economy/DefaultEconomy.asset 现在包含经济、工作时段/工资/岗位、零售价格/携货量/开店时间/资本、加工资本/成本/劳动分钟。新城冻结，保存恢复原配置；编辑资源不改已有城市。语言资源两种语言11 Key。

商业员工暂用11点开始的480分钟班次，工业8点开始；让实际人员下班购物有营业窗口。这是可调平衡近似，不是已经核实的 CS1 工作日规则。没有教育、性格或复杂企业玩法。旧建筑容量、需求、迁入钱、生产物理库存上限以及多数历史文字仍待逐功能迁移。

## 实际验证

- 2209 城市检查：实际居民去厂工作返家、有价原料、批发/零售/携货/消费、购物道路中断安全拒绝或连续恢复、任务在途恢复后完整保存逐步一致。
- 3048 新交通核心检查；独立1000/3000/10000活动车拥堵/分散测试、现有全领域回归均通过。历史引擎测试通过不代表它已接回正常城；行人/信号/垃圾仍未迁移。
- 完整消费者城市从空地经命令建设、供给、分区成长、迁入及实车运行到第8天：43人、34建筑、13道路、最多33活动车，实际消费75件，零售4500，已付个人工资8383。12,000步平均约0.050ms，P95约0.028ms，P99约0.053ms，平均12.7KB分配；一次最大约51ms，冷生长/管网/就业重建尖峰仍需归因，不能仅称GC。
- 单独无商业分区的出口测试仍验证真实出口176件；消费者城市优先本地供货，不能为了让出口计数增加而忽略商店需求。
- 测试布局修正：原入口尽头商店货车不可达，管线覆盖不足；用正常分区规则移到环网并延长管线，没有强制到岗/赠货。这是测试条件修正，不能与此前仅出口城市直接作为等价性能对照。
- 原 Unity 地形窗口：12居民、最多12活动车；1x/3x约59.99/60FPS，实际倍率0.9998/2.9876，P99约17.01/17.04ms，GC约23.9/27.1KB帧。真实到店购物与保存 continuation 通过，不代表大型完整城市FPS。
- 同一禁用私人发展公共夹具与上一批配对，比较通用工资字段、实体、钱货、车辆路径的共同语义；新零账户/派生收入累计不混入旧格式摘要。结果CSV保留，3000人公共夹具均值1.264782→1.322539ms（约4.6%增加），P99 10.1305→10.3834ms；分配均14,292B、生产/交付均5250，共同状态完全相同。新增必要账本与空在岗索引存在成本，短样本也有噪声；不承诺本批有加速。
