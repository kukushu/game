当前源码独立交通重跑：每种配置50步预热，300步计时，15模拟秒。分散1万车平均4.42388ms/P95 4.65670ms/P99 7.75500ms，分配2272.2B/步；排队1万车平均4.13704ms/P95 4.30570ms/P99 4.39100ms，分配384.1B/步。3218核心方向、安全、施工、换道、货运资金及保存继续检查通过。排队接收端明确堵住，大量车辆静止，不能把它当作复杂路口高吞吐基准。长走廊坐标也不是当前正常游戏地图；固定路线与注入任务是明确隔离夹具，不用于冒称居民业务或FPS。

万人城探测：使用原成熟城生成器、seed7919、8户公寓、当前地图、一次性建城补助1000万元，仍读取原GameData与真实建设检查，目标10日。不减少居民/设施/岗位，不跳过管线重叠检查；实际失败发生在Create返回前，故仅有输入、环境和异常，没有虚构可用的failure.hcity。它证明目前夹具未能完成这次构造，不证明人口/交通引擎不能模拟一万人。具体支管位置与合法替代布局仍待诊断，不能先断言是重叠检查本身错误。

下一批优先：

1. 查明密集水务支管构造失败，完善现有生成器的合法连接/布局；保留500/3000夹具对照，不取消真实施工校验。
2. 尽快取得10000真实居民完整基线，同时继续按实际活动车数测量，不因3000人有问题就无限停留在小城。
3. 单独处理已经实测的垃圾派车重复准备/集中寻路：这是完整城尖峰，与万辆车独立运动成本是不同路径。区分运输吞吐和CPU开销。
4. 在复杂可达路网、真实派车/到达/经济/服务条件下逐步达到10000活动车，分别测模型和可见窗口，不以固定走廊代替。
5. 再按10000→30000→100000居民扩展；每级记录初始化、长期模拟、钱货守恒、在途恢复、内存、GC、帧尖峰与真实倍率。规模是测试目标，不是性能保证。

本批没有修改模拟、业务规则或架构，没有降低工作量；只执行已有测试并记录真实失败/边界。原始证据Temp/RoadCore/scale-question-20261016*及Temp/CityScenarios/stage3-grid10000-probe均保留。轻量证据见Docs/Benchmarks/2026-10-16-ScaleProbe。
