# 未推广的SAT临时数组实验

**产品没有启用此实验**。正常CityBuilding.Overlaps仍为原实现。原型只保留Temp/CityScenarios/CityBuildings.axis-prototype.cs；回退仅恢复本批自己修改的6行，没有覆盖用户工作。

动机是冷分区分配较大，研究四轴数组能否是主要来源。原型只把同顺序的四个float轴数组改为循环生成，公式/容差没有变化。500000个确定性旋转矩形结果及接触/重叠/分离解析检查与冻结9abf728完全相同。100000次热调用Mono分配3200000→0B；局部这是真的，但不能推断整城收益。

同三万人输入，Mono固定CPU0、串行2400步：旧15.3881ms/步、P95 22.448、P99 59.263、最大1490.92；新15.6318、23.129、59.117、1526.80ms。分配214906.5→212748.9B/步，仅约1.00%减少。两城完整保存同2596b3c6f2c80fdca74941df38049ae8d519eeb5ae95a7e0b9f344e2a9a59f27。单次测量不证明慢1.58%，但也没有证明整体CPU改善。

冷4441带采样时分配233.59→228.42MB，仅少5.18MB，Geometry自身130.90→130.58MB。因此“130MB主要都是SAT轴数组”的猜想被实际数据否定；没有按猜想继续扩展几何重构。23461综合城市、6000采样开关、80预算/保存/动态施工检查通过，不以通过测试强行推广没有整体收益的改动。

保留有界工具VerifyBuildingOverlaps（-BuildingsSource显式临时源并记录hash）、确定性结果证据及步骤工具的BuildingsSource控制。它们不改变模拟规则/事实，也不进入正常Player。下一步单独观察ZoningCellKey与几何对象创建，不把全部分配或尖峰简单归结为GC。
