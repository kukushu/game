# 玩家反馈与现场记录所有权

本轮为首轮手动试玩增加只读反馈，不改变经济决策、购物/投资规则及城市19/交通16/设计5/业务10保存格式。

|所有者|事实与职责|
|---|---|
|Household / FactoryState / ShopAccount / Payroll / Utilities / Waste|继续独占库存、现金、账目、实际付薪和基础供给等业务事实|
|CityCoreObservation|保留 Read/Issues/Pick 接口；读取选中对象，解释可确认的直接原因。家庭与员工使用实体已有索引，岗位/相关出行仍按现有集合查询|
|CityPlayerFeedback|仅维护派生问题标志、家庭归属、当前受影响数量及稳定排序条目。无业务写入口，无保存字段|
|HarborCityObservationPanel|选择、滚动、分组分页、定位；最多每0.5实秒刷新，不在每次 IMGUI 绘制扫描居民|
|HarborCityFeedbackPlaytest|试玩元数据、可选案例装载、暂停后的本地现场副本/截图；不修改案例源文件或自动上传|

绑定城市时建立一次家庭/建筑统计。家庭库存/资金、成员结构/死亡/住址、企业结构/资金跨零边界、供给重建、垃圾生成/收集的通知只标脏；网络/建筑版本变化允许建筑全量失效。模拟步和边界命令结束后批量读取。家庭统计不依赖逐帧遍历居民，详情仅查询选中住宅的家庭与企业员工。问题条目按严重程度、类别、稳定建筑/家庭身份排序，同住宅同类别合并，打开清单/记录时补读代表对象当前库存及补购需要，结构化证据带观测 Tick。

切城 Bind 先 Dispose 旧观察器并解除全部事件，清空统计、选择、分页；宿主销毁同样解除。暂停读档后，Payroll 的临时付薪在岗字典尚未形成，观察器以绑定 Tick 为界显示“待模拟更新”，不把缺少缓存当作零员工。任何解释都不调用消费、供应商分配或模拟推进。

空库存、低于存档规则补购阈值分别计红/黄；家庭初始化尚未完成不计短缺，正常补购本身不等于经济故障。商店资金耗尽独立计数；无人付薪、在途、正常闭店仅显示于详情，不制造新的全城红警。原因未知明确说明，店有货但未营业不称缺货，现金耗尽不称缺工。

现场按钮先暂停并锁住输入，再读取反馈和调用 CityCoreSave.Write；保存异常保留原拒绝边界并记录，不修复/篡改城市。文件夹唯一，先写元数据，再在帧尾捕获游戏窗口，更新成功标志；任何部分失败均显示不完整。选中对象接口列表展开为记录数组，便于 JsonUtility 序列化。Tick、内部对象身份、源码版本放入结构化现场记录用于复盘。

构建入口 `CityPlayerBuild.BuildFeedbackPlaytest` 仅允许 batchmode，设置独立 ProductName，Release/Mono Windows64；`Tools/BuildFeedbackPlaytest.ps1` 在本工作树 Temp/FeedbackUnity 复制项目编译，生成源码资产 SHA256 清单，原样复制两个诊断存档并核对哈希，不运行游戏。案例原诊断地形为 y=2 平地；视图旁车 `.view.json` 通过城市文件哈希绑定，不修改城市协议，不把案例地形误当正常新城。默认入口仍是 CityNewTownTemplate。

限制：本轮明确没有运行模型或 Player 验收，增量通知覆盖、UI 输入/窄屏布局、故障时截图、保存冷恢复、实际开销待手动或后续授权验证；不能由编译结果宣称它们已通过。
