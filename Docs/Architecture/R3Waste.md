# R3-C4：真实垃圾往返运输与处理

实现提交：`b1cdb03`。HTML固定到该提交，后续文档提交不改变源码定位。

## 已接入正常城市

空城可付费建设垃圾处理场。实际住户按游戏日产生垃圾，商业/工业按居民真实出勤分钟汇总产生垃圾，不按岗位容量凭空产生。CitySimulation在固定步日界、Payroll清零出勤以前生成；暂停和显示帧不会增加垃圾。当前整数速率、每日截断和收集规则是项目近似；处理场持续处理垃圾是用户明确要求的原版例外，不冒称CS1原版垃圾填埋规则。

垃圾链：建筑garbage → 空车实际到楼下 → 同车装载Waste Shipment → 沿实际返程行驶 → 场内stored → 按固定时间处理。没有原地清除全城垃圾，没有货物瞬移，也不把废物变成商品或财政收入。

## 所有权与车辆生命周期

- CityCoreWaste拥有WasteServiceData：累计产生/收集/处理量、日界游标、派车时刻和WasteMission。city.waste引用同一份既有累计事实；保存只保存服务数据中的一次副本，Validate拒绝更换别名。没有往World加入企业/垃圾业务。
- CityBuilding.garbage和LandfillBuilding.stored/processingRemainder仍是各实体唯一库存。任务装载后由Shipment独占在途垃圾；Mission只记车辆、当前任务、处理场、收集目标与Pickup/Return阶段，不复制货物数量。
- 一次任务周期只占一个真实车队名额，去程与返程保持同一Vehicle和VehiclePosition。到楼下以后替换下一段TripTask和RoutePlan，不重建位置、不把车改放到另一侧车道。回场卸货才退休；下一次工作重新派车。目前不是持久停放的车库资产，也不是多站巡回收集。
- TransportPurpose.Service区别于居民和普通贸易。服务车使用实际车道、换道、跟车、路口预约和既有动态施工规则；不能被居民校验器误当成Citizen，也不进入商品/进口资金结算。
- PrepareServiceReturn从当前Drivable/Distance预检返程，允许目标入口的现有双侧接入，但绝不换一个源位置。路线、ID和编辑epoch先检查，再同步扣建筑垃圾并提交下一段任务。旧任务在本次统一到达结算末尾集中退休，避免每次装载扫描任务列表。
- 不通时不装载，原车留在原地等待。道路拆除时冻结真实位置并保留任务/货物；恢复道路后走已有原位恢复链。重复到达、过期交接和旧任务引用被拒绝。

真实守恒检查：generated = 活跃及退休建筑garbage之和 + 场内stored + 在途Shipment + processed；collected = 场内stored + 在途 + processed。UI待收量由守恒累计差推导，避免每次OnGUI再遍历全城；冷Validate独立逐实体核对，不用同一公式自证。含垃圾/待处理库存的建筑暂拒拆除；在途任务引用也阻止关闭。实体替换不得抛弃已有垃圾库存。

## 性能证据与边界

与05ff413共同的3000居民旧原型夹具配对：均值1.301346→1.309386ms，分配同为14292B/步，产量/交付5250、共同语义及交通状态一致。差异约0.6%，在波动范围，不宣称加速。夹具显式关闭城市发展/垃圾，仅检验新空门禁和既有交通不退化；不是垃圾大城性能证明。排除新停用字段时额外断言垃圾累计/任务必须为0。

真实原地形消费者城12000步：30人、27建筑、第6日、峰值32车、消费45。带采样完整步平均0.034432ms、P95 0.053、P99 0.1108、最大14.1061；Unity原始Hierarchy实际分配3687B/步。Waste两处门禁/步共24000次，总平均0.000560ms/步、P99 0.0024、39B/步（包括低频派车与日界）。这些小样本包含采样成本，不外推10000居民完整城市；最大尖峰仍在生长/分区几何和供给重算。

Unity线程分配计数不支持时继续报告-1，实际GC从Hierarchy导出；父子分配不可重复相加。原始178MB级Profiler留Temp/RoadCore/GrowingProfile-waste-final，提交仅modules/spikes/metadata摘要。

1k/3k/10k实际车的内核回归继续运行；最终孤立10k车均值分散4.306ms、合流4.165ms，分配2272/384B每步。这不是完整城市FPS或10000辆垃圾车验证。正常窗口与带采样步成本分别报告。

复杂度：处理O(处理场数)/步；日界生成O(居民+建筑)一次；派车每2模拟秒构造候选和已有任务预留，O(B log B + M + F*B)最坏候选查询，成功与失败路径复用既有有界缓存。车队和在途容量从Mission/Shipment推导，不保存另一份可写预留表。尚无大城垃圾调度局部空间索引，远距离/大量不可达目标需要后续真实城市Profiling。没有把查询藏进接口后声称O(1)。

Profiler路径：City.Simulation.Step → City.Simulation.Waste（处理/调度），City.Simulation.WasteGenerationBoundary（日界产生），City.Simulation.Settlement（到站装载/卸载）。归因构建展开City.Attribution.Waste及RouteSearch/Admission；普通构建不启用CITY_CORE_ATTRIBUTION。
