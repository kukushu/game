# R3-D3：选择实际道路并升级、反向、拆除

实现提交：`f6d00f3`；HTML固定此源码定位。

## 正常入口的操作闭环

点击“选择道路 / 升级 / 拆除”，再点击道路路面。高亮的是选中逻辑道路的共享中心线，不是任意几何采样短边；面板显示真实ID、长度、每个可通行方向的车道数和方向。可以改成每方向1/2车道，切换单行/双向，对单行反向，或拆除该路段。Esc或“结束道路编辑”退出。原来“升级/反向/拆分/拆除第一路”的四个临时按钮已移除，不能再误改固定ID=1。

工具与修路、分区、设施/管线、对外连接、观察互斥；面板拦截地图建设与相机滚轮输入，财政模态仍优先。换城重绑会清空旧道路ID/提示/高亮。路网变化时检查ID还存在才重画，否则清空；不长期保留已删道路所属的旧Network引用。

本批恢复的是地面道路的选段编辑，不是原版全套道路工具：地形鼠标射线尚不能直接选择地下/高架层；模型查询已验证三维高度区分。道路曲线预览、层级选择、桥隧高度工具、自动拆迁安置、编辑撤销、完整类型目录仍未恢复。不能把这一批视作CS1道路体验已经复刻完成。

## 唯一事实与事务边界

World的物理道路/共享几何仍是唯一道路事实，稳定Road ID不等于Drivable/Lane ID。Network.ContainsRoad只增加O(1)读查询，未创建道路副本。空间索引按不可变Network派生并惰性构建，选路由三维位置查局部车道候选再取所属物理道路。

HarborCityRoadEditor只拥有工具模式、选中ID、上次绘制的网络身份、LineRenderer和提示。高亮依据Centreline，只归视图；不修改Transform来移动真实道路/车辆。没有把选中道路存入城市或增加第二份位置。

CityCoreConstruction.UpgradeRoad在健康边界根据当前ID和参数新建RoadEditPlan，沿用World完整候选/占用/引用迁移校验，再沿用财政预检/提交，成功才扣费。UI不跨显示帧缓存预览Plan。相同参数返回0且不换Network/道路版本，视图也不触发Changed整城道路重建。反向/减车道遇到实际车辆占用会明确拒绝，不撤销车辆、不跳位置；拆路沿用原位中断并保存任务/货物的规则。所有业务仍由CitySimulation固定步推进。

新增一项必要城市校验：拓宽道路若侵占已建建筑，预检拒绝、资金与城市保持原样。当前没有自动拆迁安置，不能让新路默默穿过房屋。CityRoadClearance从原CityCoreZoning.CanPlace精确提取既有三维车道带/建筑矩形判断，两处共享同一算法，不维护另一份可编辑几何。升车道时对候选Network逐建筑验证；不修改实际建筑、住房或岗位。待建私人项目仍由既有Growth规则在下一健康边界重新校验/取消。

道路成本继续使用已存在的Quote/维护规则，没有新发明平衡参数。旧道路价格常量仍待后续Roads数据分组迁移。新提示/方向/操作文字集中资源，中英文共116 Key。城16/业务8/设计4/核15格式不变，UI状态不存档；旧文件/原始采样保留。

## 可重复验收

1. 从空城修两条以上道路，打开道路编辑并点选第二条，确认高亮和ID不是第一条。
2. 在没有建筑/车辆妨碍的街道改为每方向2车道，资金按实际增量扣除；重复同参数不收费、不重建。
3. 改单行再反向，实际寻路方向随之改变，不是只改颜色。保存、读取并继续。
4. 在占用方向的道路尝试反向，或在已建房屋旁尝试拓宽；明确拒绝，车辆/房屋/资金/存档不变。
5. 拆除有实际出行的道路，观察车辆仍在原位、任务/居民/货物仍存在，并验证中断在途保存。

程序测试覆盖上述模型行为；Unity运行验证使用同一实际成长城市加建一条正常付费街道，程序调用工具命令选中非第一路、拓宽/单行/反向、精确在途保存继续、拆除和失效选择拒绝。已查看实际工具/高亮截图；没有宣称人工逐个点击鼠标完成验收。

- 3218道路内核检查、6000步采样开关完整保存对照、岗位分配与原全领域回归通过；原信号/行人/医疗等旧测试通过仍不代表接入新城。
- 同一成长消费城12000步、30居民/26建筑/13道路/峰值34活动车：c30402d与新实现完整保存SHA相同、消费36件/2160支付相同，分配同为3449B/步。共享碰撞判断提取没有改变分区/生长行为。
- 第一次配对与Unity构建/其他回归并行，均值0.014936→0.018210ms；该受干扰记录保留。等待所有已确认进程结束后复测0.014606→0.014668ms，P99 0.0424→0.0435、最大6.592→6.634。未宣称加速，差异约0.4%在小样本波动内。
- 正常Unity窗口从同一真实服务车在途保存分别运行1x/3x，打开并选中道路工具；12居民/18建筑/3服务车峰值，1x/3x约60FPS、实际0.9960/2.9990倍率、帧P99 16.917/17.062ms，整体GC 30077/39753B每帧。数据见Results/R3RoadEditing/native-window.csv，不用孤立内核代替FPS。
- 实际原地形成长城市加建非第一路12，建设750、拓宽750；原有实际车辆的位置与Task不变。工具完整升级约8.86ms、单行+反向两次约14.89ms、拆除约9.05ms（单次样本，含道路Mesh刷新；非模拟步，不是大城延迟承诺）。完整编辑城市读档继续相同。

复杂度：首次空间查询惰性建立O(几何样本)索引，以后按局部候选查询；高亮仅在选择/Network变化时按该路采样数重画，平帧只比较身份。施工提交仍有全量Network和车辆冷校验，费用Quote遍历路网，拓宽校验O(B * 局部候选)并可能首次建立候选空间索引。没有把这些冷成本隐藏成常量时间。

顺便去掉新工具回调里不必要的整城分区/建筑刷新：道路Mesh立即更新，分区由现有Update按NetworkGeneration在下一显示帧更新一次，建筑位置未改变。旧区域与道路全量视图重建仍是过渡风险；工具耗时不含延迟到下一Update的分区刷新，不能拿前后计时范围变化当作总体加速。大城施工尖峰和预览仍需单独Profiling。
