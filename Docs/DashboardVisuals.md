# F3 Dashboard 视觉结构

数据流继续为 Simulation → CityDailyAnalysis → CityAnalysisState → IMGUI。`CityAnalysisState` 与 `CityDailyAnalysis` 未修改。UI 只从已经提供的结构化状态取数，计算展示比率、图表坐标、条长和简单状态颜色；不进行候选评估、发车、付款、随机调用或回写模拟。

## 首页

顶部给出当前日时、关注提示和今日产销。两行 KPI 卡片展示人口、就业率、空置住房、平均实际通勤、财政、居民在途、货运在途及库存 / 资金异常工厂数。异常工厂为原料为空、成品仓满或现金耗尽的去重计数，来自已有 BusinessAnalysisState，不能将三个分类计数相加当成工厂总数。

卡片下方是 Findings。默认展示前 3 个，可展开全部。每个卡片只显示简短标题、已有证据中的关键量和“查看”按钮，完整解释仍在实体详情。随后是交通 / 工业状态、Today 四种真实流量、劳动对比条和资金 / 城市变化。

Today 的生产、实售、运出、原料实际入库采用本日最大值作为相对尺度。运出不当作实售。劳动条明确标注工人分钟，分别展示实际在岗、有效加工、缺料受阻、仓满受阻和资金受阻；未假设这些量必定相加等于总在岗时间。

## 可复用 IMGUI 组件

`HarborCityDashboardVisuals.cs` 提供 MetricCard、ProgressMetric / ProgressBar、MiniBar、StatusBadge、SectionCard、FindingCard、FieldRow、Sparkline 和 LineChart。高亮值、短标签和详细证据分开；字段与条形数据对齐。

GUIStyle 缓存；背景和条使用 Unity 内置白纹理。折线通过有限数量的可复用图表纹理绘制，避免滚动区中旋转 GUI 坐标导致越界。历史变化或图表尺寸改变时才更新像素；未变化时复用。组件关闭时释放纹理。不逐帧创建 Texture2D 或 Material。

`CityDashboardPresentation.cs` 为纯展示数学与颜色映射，不引用 Unity 或 CityModel。图表范围支持空历史、单点、零值、平线、负数以及未知值。按真实 day 横坐标绘制，不把数据行号当作时间。

## 经营、History 与其他详情

工厂：当前现金与今日经营盈余做数字卡片；原料、成品、岗位、当前在岗、加工和今日到岗做进度条；收入、原料支出、实付工资、加工成本做收支对比条。所有今日财务仍是原来的累计差量；经营盈余包含预付采购，累计收支另列。商业没有独立现金账，继续只显示真实库存、补货和雇员，不虚构利润。

History 绘制人口 / 就业、财政、平均实际通勤、工厂生产 / 实售四组序列；旧日账目没有工业观察时留空，不连接空白。工业部分日为橙色独立点，不与完整日连线。可展开原日账目明细。

人口、财政、通勤卡片使用最多 30 个已结束日的小折线。就业卡片优先显示就业率和真实劳动者分母；就业人数趋势放在 History。没有历史时显示不足提示，没有当前通勤样本时显示“—”。通勤历史沿用日账目均值，0 可能表示无样本，界面明确提示。

家庭 / 居民采用对齐字段和分组，保留候选、实际决策证据以及居民 / 家庭 / 工作场所导航。城外迁入或旧方案已失效时显示“无有效当前方案”，不把评分占位值当成真实改善；只有经过评估且两边方案均有效时才比较评分。Timeline 使用独立日期时间列、竖线、小状态标记和单句事件，仍可进入实体详情。搜索、分页、定位、跟随、Debug Trace 和 JSON 导出入口保留。

## 颜色

灰蓝为中性数据；已确认资金问题为红色；已有缺料、仓满、缺货、运输和就业 Findings 为橙色；明确恢复状态或已提交且评分改善的家庭变化为绿色。颜色是对已有 code / state 的展示映射，不改变 simulation severity，也不按任意数值阈值创造严重程度。未知 code 保持中性。

## 验证与预览

`Tools/Verify.ps1` 原有 333 项检查通过，新增 21 项图表与展示语义检查，共 354 项。包含真实日期轴、缺失工业数据、部分日、零值 / 平线 / 负财政、比率边界、未知状态保持中性、无效住房评分不参与比较和展示数学不改模拟。

运行时与编辑器脚本分别编译。Unity 实际 Game 画面检查首页；`Harbor → Preview Dashboard visuals (isolated test city)` 使用实际 Dashboard 绘制方法和独立运行的测试城市，可检查工厂、商业、历史、家庭、居民和时间线，不推进或保存主游戏。
