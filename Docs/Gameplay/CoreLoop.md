# HarborCity 核心玩法循环

本文件用于持续记录用户讨论和确定的游戏玩法。始建于2026-11-04。

当前原型实际行为另见[2026-11-04玩法快照](CurrentGameplay-20261104.md)，与本文件的设计方向和候选建议分开阅读。

## 记录约定

- 记录玩家行为、触发条件、游戏反馈，以及居民、家庭、企业与城市发展之间的因果关系。
- 玩法设想、待定问题和已确认规则明确区分；未确认的想法不自动成为正式规则。
- 不记录代码架构、算法、性能优化或测试基础设施。
- 用户后续讨论核心玩法时，在此逐步补充；不主动编造完整玩法，也不直接把现有原型实现当作已确认设计。
- 玩法记录本身不授权修改游戏代码。

## 已确认的玩法规则

### 首轮商品范围

2026-11-04，用户决定先简化设计，商品只设两种：**食物**与**日用品**。

后续批准的首轮细则如下。实验分支已实现这一循环，验证范围见[实施记录](../Architecture/TwoGoods-20261104.md)；不代表已经合入正式开发分支或完成长期平衡验收。

### 两类商品首轮规则（2026-11-05接手核对）

- 玩家提供用地、交通和服务，企业依据真实缺口自主投资。工厂开业后固定生产一种商品，综合商店销售两种；首轮不做迁址、转产、股东分红或市场模式切换。
- 工厂启动资本1200、商店2000，来自明确记账的外部投资；建筑本体造价暂不另算。
- 家庭共享库存。每人每天消耗食物1份，每7天消耗日用品1份；食物不足1天时补到3天，日用品不足2天时补到14天。迁入携带上述目标物资，记录为外部带入。
- 一户同时一个购物周期，一趟最多32份。食物优先，买不到食物时保留其预算，不自动挪给日用品。到家才转入家庭库存，消耗另行发生。
- 取消17:00及每日一次限制，每1模拟秒仍保留购物决策检查时刻。缺货记未满足需要，不产生负库存，不追扣全部历史欠缺；本轮不因此改变健康、死亡或迁出。
- 食物零售20、批发15、每份劳动15工人分钟；日用品60、45、60工人分钟。共用原料成本8，加工费均2；这些是试验参数，尚未完成平衡验证。
- 综合店总容量32；两种均有需要时按真实需要比例分配补货目标，食物优先取整且两类至少各1份，避免一类永久占满空间。
- 商业与工业投资保留6秒检查及施工周期。无可达商店才形成开店需要；有店缺货先补货。工厂按真实采购缺口选品，扣除现存货物、在途和待建预留，平局食物优先。
- 投资须有合法地块、道路和符合岗位条件的待业居民；靠近缺口选址，新厂首交付前暴露阻塞并避免同类重复建设，项目结束释放预留。住宅需求原规则保留。

账户、库存和实际交易可形成真实反馈，但本轮并未实现居民储蓄人格、动态定价或完整迁入决策。普通小城已观察到食品厂资金耗尽、日用品成交不足，不以额外注资或修改税费掩盖。

### 商品细分的价值讨论（待定）

2026-11-04，用户要求比较其他游戏，重新讨论食物/日用品区分对本作的价值，尚未撤销两类商品范围，也未确认具体机制。

- 助手建议：只有当两类商品在家庭取舍、短缺反馈或玩家应对方式上产生实际差异，细分才值得；若只是名称和库存不同、决策与后果完全相同，暂不增加该复杂度。
- 候选方向：食物代表较难推迟的基本开支；日用品作为另一类消耗较慢、有补购弹性的综合商品。具体必要程度和短缺后果仍待定，不直接规定饥饿致死或日用品缺失伤害。
- 目标是让收入变化影响家庭支出结构，再影响不同商店的真实营业收入和经营结果；玩家通过就业、生活成本、供给及可达性等城市条件应对，不要求逐户手动采购。
- 微观交易产生宏观结果并不要求商品种类繁多；少量商品也可以承载真实工资、购买、库存和经营反馈。
- 参考：Colossal Order《都市天际线II》2023年经济开发日志（设计说明，不等同当前版本逐项实测）https://colossalorder.fi/news/development-diary-9-economy-production/ ；《工人与资源》官方Wiki居民需求 https://wiki.hoodedhorse.com/Workers_Resources_Soviet_Republic/Units ；《纪元1800》官方更新16的消费需求说明 https://www.anno-union.com/updates/anno-1800-game-update-16/ 。参考游戏的机制不自动成为本作规则。

### 家庭迁入的基本方向

用户认可先围绕家庭安顿建立循环：可负担的住房、获得收入的机会和可接受的基本生活条件是迁入意愿的考虑因素。具体门槛、权重和判断方式尚未确定。

### 微观行为形成宏观结果

2026-11-04，用户明确提出：

- 城市的宏观指标应从居民、家庭、企业等微观主体的实际行为与交易中涌现。
- 不采用“住宅区扩大多少，商业需求就按固定比例增加多少”作为需求产生的根本机制。
- 收入、支出、资金流转和交易应有真实业务依据；需求不能只由分区面积或总人口的预设比例推导。
- 居民具有个体差异，而不是所有居民执行完全相同的消费选择。用户举例：有人储蓄意愿高，倾向于保留收入；有人储蓄意愿低，更愿意消费。具体数值与决策规则未定。
- 用户关注真实经济过程及其形成的结果，尚未要求永久保存每一笔交易流水；记录与展示方式另行讨论。

## 待讨论：居民特性如何影响选择

### 特性进入玩法的判断原则（用户已确认的设计方向）

2026-11-04，用户强调，每新增一个居民、家庭或企业特性，都应审查它参与的循环与反馈：

- 它会影响主体的哪些实际选择，进而影响哪些其他主体或城市状态？
- 后续结果如何反馈，改变主体之后的处境或行为？
- 玩家能通过什么表现观察并理解这些结果？
- 玩家有什么有意义的手段应对或影响这些结果？玩家不必能直接修改特性本身。
- 避免只增加属性数量、没有实际玩法联系的细节。用户以头发长度、身高为例：若不影响行为、有效表现或玩家决策，就没有必要作为核心模拟特性加入。这不是禁止外观细节，而是要求核心玩法特性有明确用途。

后续讨论候选特性时，应说明“行为影响 → 后果与反馈 → 玩家可见表现 → 玩家应对手段”；缺少环节时先保留为待讨论，不凭真实世界存在该差异就直接加入。

### 尚未确认的候选

以下为助手补充的候选，尚未确认：

- 消费与储蓄取舍：在基本生活需要、当前资产和未来收入预期下，决定可选消费与留存资金。
- 生活偏好：对商品类别、品质和价格的偏好影响实际购买选择。
- 居住与通勤取舍：对住房支出、居住环境和通勤时间的容忍度影响住址及工作选择。
- 稳定与风险取舍：对收入稳定性和更高收入机会的偏好影响换工作等决策。
- 个体偏好、当前状态与外部条件应区分；偏好不会保证交易发生，还需要可负担、商品可得等条件。未满足的需要不等于实际成交。

## 建议的改造起点（待用户确认）

2026-11-04，基于当前玩法核对，助手建议先完成一户家庭的收入—生活支出—储蓄—消费反馈，再扩展迁入与企业发展。此为讨论建议，不是已批准的规则或代码任务：

1. 明确家庭预算与个人偏好的关系、生活需要、储蓄目标，以及买不起/买不到时的后果和玩家应对手段。
2. 复用已有真实工资、库存、付款和出行，把统一购物触发改为有原因的家庭消费决策；消费意愿、购买能力、可获得性和实际成交分别表达。
3. 让商店经营结果及玩家商业信息反映真实顾客、成交和未满足需求；区分缺货、买不起、无法到达，不简单把所有未成交需要算作新商店需求。
4. 再研究企业招聘/扩张与家庭就业选择，最后把住房选择和迁入接入这条反馈链；具体先后可随依赖审查调整。

先记录现有初始资本、城外收支和费用去向，不把当前原型宣称为封闭经济，也不为追求闭环而未经讨论删除资金来源或强迫家庭消费。首轮用小城观察高/低储蓄偏好、失业、缺货与交通中断的因果与玩家反馈；城市人口增长不是唯一成功指标。

## 早期候选循环：让一户家庭在城市里安顿下来

2026-11-04，助手提出以下候选方向，尚未经用户确认，不作为实现要求：

- 玩家提供可入住的住房、可获得收入的就业机会和基本公共服务，吸引家庭迁入；具体门槛、判断方式与数值待定。
- 家庭通过工作取得收入，并产生消费与服务需求；企业提供岗位、商品并获得经营收入。
- 玩家观察住房、就业、商品和公共服务之间的缺口，决定扩建或改善哪一项；城市发展提供财政收入，也增加建设和服务支出。
- 候选核心循环：创造生活与就业条件 → 家庭迁入并工作消费 → 暴露真实供需缺口 → 玩家投资改善 → 城市承载更多家庭。
- 住宅需求应表达“还有多少家庭愿意来却缺少合适住房”，不能仅由已有总人口直接推高；是否维护城外候选家庭等具体机制待讨论。
- 优先讨论一户家庭迁入、就业、消费与安顿的完整过程，再扩展成长周期；先明确玩家的决策与反馈，不急于确定公式。
