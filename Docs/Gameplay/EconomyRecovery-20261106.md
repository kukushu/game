# 小城循环修复记录

## 第一阶段：经营判断与就业恢复

基线 `c9d5122`。工厂扩建判断加入一班次的供给上界，受真实原料（含在途）、现金、健康合格员工、仓容和水电限制；同一份供给在不同商店之间仅分配一次。上界不是保证交付，运输或营业窗口仍可能使其落空。

企业无钱且没有在途货运时，已回家、无携货、无活动任务的员工释放岗位，保留已赚工资。求职先给没有资金正常的雇主岗位的家庭一次机会，再分配额外家庭劳动力；不强制改动已有工作，不招用生病居民，实际岗位仍按技能和路径选择。

两商品专项 1,254 项通过，包含新增恢复边界、在途回款保护、家庭求职优先和共用供给检查，保留参考轮询/事件版及冷恢复对照。核心回归通过 20,960 项产业/居民、10,000 岗位索引、1,522 网格、83 分区、460,474 水电检查。检查计数包含运行路径中的断言次数，会随模拟行为改变，没有删除或放宽原断言。

以下为 Unity Mono 固定步结果，均有真实进口道路，没有修改初始物资或中途注资。生长城人口随决策变化，不是同人口配对。密集 120/502 人为预置多企业压力场景。

| 输入 | 天数 | 末人口 | 断粮户 | 累计食物/日用品成交 | 末七天成交 |
|---|---:|---:|---:|---:|---:|
| 原基线默认、生长 | 90 | 84 | 28/28 | 602/0 | 0/0 |
| 第一阶段默认、生长 | 90 | 120 | 40/40 | 1920/293 | 0/0 |

结论仍是经济验收失败。交易增加不能证明持续经营。独立的一人企业 SmallBusiness 候选（早于家庭求职优先改动）到 90 天有 9/11 户断粮，三家企业均有现金；缩小企业规模不能单独解决家庭收入。

`Tools/RunSmallEconomyStudy.ps1` 新增 SmallBusiness 候选与末态逐户 `households.csv`。原始结果在 `Temp/EconomyRecovery-20261106-*`，各目录有输入源码哈希、每日资金流水、末态存档和日志。旧城不被覆盖。

## 第二阶段：开放城外市场

用户已选择开放城外市场，明确记录外部付款，以订单量和实际运输限制成交，不模拟整个世界固定钱包。第一阶段 Pilot 到 90 天城外仅余 104 元，已不足部分整车出口订单；此前固定 100,000 元钱包不适合作为这个边界。

已实现全城每日分品类订单，出发占单并记录外部预付，到达结算。订单计数和日期保存，跨日和多出口不重复领单。校验预付=已付+在途，并核对进出口实际数量×冻结单价。工业投资可使用未覆盖外部订单，已有可达工厂的一个满班产能及待建预留先抵扣；新外销项目规划、完工都检查进口和出口方向的合法路线。该产能是上界，尚未把共享进口车辆的实际吞吐折算成可靠生产能力。

求职额外核对企业能否负担下一班已有工资及新增工资。商店保留一名启动店员的招聘机会，新增店员的工资和岗位税不能超过已绑定家庭正常消费量的毛利。招聘人数不是建筑最大岗位数，也不是“补三天货”的瞬时需求。已有合同不因这一规则自动裁减。

迁入条件复用招聘资格，避免空岗位却无实际招聘预算仍吸引家庭。启动时允许四名成年劳动力先来安顿。已有家庭和居民不会因规则被删掉。缺少本地合格劳动力但有空住宅时，企业可先投资形成招聘机会，实际到岗前不记劳动、工资或产量。首交付失败且已无钱、无货、无在途的工厂不再永久阻塞同品类替代投资。

新版 Player 配置 `open-town`，价格、工资与日长见数值文档；`GameDesignData.OpenTown()` 为命令行同配置入口，默认 DTO 保留原数值参考。研究脚本 `Current`/`OpenTown` 使用新版配置，`LegacyNumbers` 使用原数值但执行新版规则，不能称作旧代码对照。

### 小城结果与未解决项

下面全部为带真实进口的 Mono 模型运行，不是实际 Player 试玩。城外订单是每种商品每天的上限，未到货不算收入，没有中途注资。36/84 人是空城逐步迁入的结果；120/500 人为固定预置人口和多企业的压力输入，未通过删居民制造通过。

| 新配置输入 | 天数 | 人口 / 户 | 末态食物 / 日用品用尽户 | 末七天食物 / 日用品成交 | 零现金店 / 厂 |
|---|---:|---:|---:|---:|---:|
| 默认每品类128订单，自然生长 | 120 | 36 / 12 | 0 / 0 | 247 / 36 | 0 / 0 |
| 每品类512订单，自然生长 | 120 | 84 / 28 | 6 / 4 | 448 / 63 | 0 / 3 |
| 预置120人，默认订单 | 90 | 120 / 40 | 40 / 40 | 0 / 0 | 10 / 6 |
| 预置500人，默认订单 | 45 | 500 / 167 | 167 / 167 | 0 / 0 | 42 / 36 |

36 人城第 15、30、45、90、120 天日末都没有库存用尽，商店一直一家且有现金。最后七天商店现金净增 191.52、工厂净增 19,419.89。增加每模拟秒一次的诊断采样后，仍发现日内短缺，整个120天观察到最长连续食物用尽 5.33 游戏小时。每天的缺货户小时数、最长连续时长和逐户收入均留档；采样间隔对应四游戏分钟，不能声称没有更短缺货。

84 人城末期仍有收入中断的家庭及买不到货的家庭，末七天商店现金下降约 220.77。增加订单不等于进口和运输吞吐增加。120/500 人场景有大量商店启动后亏空，当前没有完整的企业缩编、清算、重组和有担保周转借款机制。不能把本阶段称作百人城市通用平衡完成，不能靠反复建店注资掩盖失败。

新的经验是，保证逐笔守恒仅能说明钱货没丢，不能保证企业有利润、收入分配合理或时间窗口足够；改善其中一项，可能暴露下一项。后续应优先针对过密商店的持续亏损和库存变现、外部订单与进口吞吐配合、失业家庭再就业继续单项对照。已验证的小城窗口保留为正对照。

原始数据在 `Temp/EconomyOpen-20261106-final-grow`、`final-84`、`final-120`、`final-500`，均有源码哈希、每日 CSV、逐户 CSV 和末态存档。各目录名的公共前缀都是 `Temp/EconomyOpen-20261106-`。未运行三万/十万人或自动 GUI 试玩。

### 存档与试玩

城市格式 20、业务 11、设计规则 6。旧版本默认文件名与新文件名不同，明确拒绝旧格式，不迁移或覆盖玩家存档。正常新城西侧中央通道已连至边界并登记双向贸易端点。格式20的问题案例来自本轮已保存的120人失败对照，供手动加载，构建不运行模拟；旧格式19的案例保留原处。

第二阶段验证：两商品专项 1,264 项通过，包含按日/商品限制外部实际发货、外部付款逐单对账、零外部订单负控、在途冷恢复后与原会话跨日完整状态对照、格式19拒绝和失败首交付替代。城市核心回归通过 23,300 项产业/居民、10,000 岗位索引、1,522 网格、83 分区、460,475 水电/道路及新城模板检查。原进口同任务重启付款断言仍保留。353 个中英文键及占位参数一致。Release 构建会额外核对实际经济资源与 OpenTown 对照配置完全一致，并只读验证两个问题案例，不推进它们。
