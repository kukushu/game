# 第一阶段：道路与沿路分区最小实施方案

更新：2026-10-10。状态：已授权并开始实施，不逐阶段请求确认。本文保留第一阶段范围与设计依据；实际代码与验证进度见 [实施进度](CS1ImplementationProgress.md)。以 [开发路线](ProductRoadmap.md) 和 [复刻基准](CS1ReferenceAndGaps.md) 为上位范围。

## 本阶段交付边界

玩家从外部连接开始修基础道路，再沿路划住宅、商业、工业用途。道路与分区预览一致，路口、土地冲突、实体占用和道路变化有明确处理，保存重启仍保持规划。

这是城市生长的土地基础；建筑生长、税收、真实供水供电与服务留到后续阶段。本阶段不能用手动放楼伪装区域生长，也不以人口上涨作为验收。保留住宅详情现有布局，不扩展家庭经济。

## 数据与现有代码的最小改动

以下为建议结构和文件职责，名称不是已经存在的实现。

| 数据 | 职责与持久化边界 |
| --- | --- |
| `CityZoningState` | 保存土地用途、稳定规划标识与必要的沿路定位信息；住宅/商业先低密度，工业先通用。高密度和办公按解锁阶段接入 |
| `ZoneBlock` / `ZoneCell` | 表达沿路方向、侧别、列与深度、世界空间几何；不能按全地图固定方格索引绑定建筑 |
| 分区用途 | 玩家指定的规划事实，与可建设状态分离；重算几何不能无条件丢失用途 |
| 有效性与占用 | 道路、路口、地形、水面、重叠与建筑足迹产生的派生状态；建筑占用引用稳定 buildingId，建筑事实仍以建筑实体为准 |
| 道路沿线身份与变更结果 | 支持几何采样和交叉分割后追踪受影响区域；当前 stroke 是施工批次，不能未经处理直接充当稳定沿路地块身份 |

复用 `CityRoads.cs` 的节点、边、曲线与交叉分割，不重写道路图。为提交、拆除、撤销统一提供道路变更入口或结果，覆盖所有修改路径，触发分区更新。预览不得修改正式模拟数据。

新增 `CityZoning.cs` 管理规划与有效性，分区渲染和输入各自单独承接职责，避免把全部逻辑继续塞入 `HarborCityGame.cs`。复用建筑占地与施工几何检查，区分公共设施付费放置和以后私人建筑生长；不能让生长直接继承现有政府付款行为。

## 尺度与生成顺序

1. 冻结参考版本、基础道路类型和单位转换。当前道路宽度约 2.7、建设范围 168×168 世界单位，不代表原作米制尺度。四格分区深度有公开依据，格宽与具体道路宽度先核实；必要时调整单位或地图容量，记录变更。
2. 把相邻采样边整理成可用的沿路线形，再生成两侧地块。曲线每条小边独立生成完整网格会造成重叠和碎片，不能直接采用。
3. 依据道路方向构建本地格子，检查道路占地、路口避让、地形和水面。斜路沿自身方向，不强迫贴合全城坐标轴。
4. 处理道路两侧、相邻道路和曲线的重叠。候选几何算法可用距离及稳定标识做确定性裁决；这是我们的实现方案，需按原作可观察结果验证后定案，不能称为已确认的原作内部算法。
5. 标记已有建筑的真实足迹与占用。重算分区不得移动建筑、改其 ID 或仅因重新分块删除建筑；生长、退化与拆迁规则在对应阶段单独实现。

路口避让距离、曲率下网格布局和冲突优先级尚待原作核对。实施前先记录矩形、斜路、弯道、T 字路口、近距离平行路五种参考案例。

## 工具与操作

- R/C/I 工具涂画用途，取消分区清除用途。先完成点击、拖动，再在同阶段补框选、填充及画笔大小，使基本操作逐步接近本体。
- 只命中可分区的土地；颜色、命中范围和生效范围一致。道路施工及分区工具显示沿路规划，不让旧单栋建筑预览代替它。
- 已有建筑占地不能在同一空间重复生长。改变分区是规划修改，不在输入回调中立即删除建筑。
- 现有普通建筑手动放置退出正常 R/C/I 工具路径，必要时保留为明确隔离的开发工具。公共设施沿用适用的放置校验。
- 外部连接先成为可看见、可接通的道路入口；完整高速规格与对外车道归第四阶段，第一阶段若采用简化入口，明确记录差异。

不大改现有住宅详情，也不新增无关管理面板。分区工具和覆盖层是本阶段必需的建设交互。

## 道路修改与保存

道路增加、交叉分割、拆除和撤销后，按受影响范围重算规划几何与有效性；无关区域不被重置。用途按稳定沿路关系及空间对应保留，冲突需有确定结果。道路删除后不能留下仍被当作可开发的幽灵格子。

原作道路拆改后是否保留某些分区意图、何时移除失去道路的建筑，仍待实机核实。先验证这些案例再确定清除策略，不将“全部清除”或“全部永久保留”作为未经核实的复刻规则。既有建筑的生命周期与土地几何更新分开处理。

扩展 `CitySaveData.cs`，保存分区用途、稳定引用、必要道路元数据、地图标识与单位配置；更新存档版本。可派生的几何与占用按加载后的实体重建，并验证一致性。加载先校验临时状态，再替换当前城市；坏存档不能污染运行中的城市。沿用并验证已有替换写入流程。

不要求迁移旧开发存档；明确提示不支持的格式。当前阶段新建的存档必须可靠，不能因重载重新分配规划或建筑身份导致用途串位。

## 实施顺序

| 步骤 | 可审查结果 |
| --- | --- |
| 1. 参考案例与尺度 | 版本、设置、五种道路案例；基础道路和分区尺度决定；未确认规则清单 |
| 2. 数据与变更入口 | 规划事实与建筑事实分离；道路提交、拆除、撤销均触发一致更新 |
| 3. 几何与覆盖层 | 直线、斜路、曲线、路口、重叠及占用正确；先验证再接涂画 |
| 4. 分区操作 | 点击拖动、框选、填充、取消；R/C/I 工具不直接创建建筑 |
| 5. 编辑与存档 | 支路、拆除、撤销、重铺后更新；保存重启一致，坏存档保留当前城市 |
| 6. 实际验收 | 下面流程在编辑器和独立运行版本重复；记录与原作差异并修正 |

## 可重复验收流程

1. 新建空城。确认没有预建住宅或居民，连接外部入口，建设一个矩形街区。
2. 三条街分别划 R/C/I，浅划与深划，框选、填充、拖动及取消分区。检查预览、实际用途与可开发深度。
3. 延伸斜路和曲线，加入 T 字路口及近距离平行路，检查重叠、路口和水面、坡度限制。
4. 通过隔离的开发样本放入独立建筑实体，检查足迹占用；道路更新后实体不串 ID、不漂移、不重复占用。这是占用校验样本，不算建筑生长验收。
5. 在有分区的道路上加支路、拆除、撤销和重铺，对照原作相同操作，确认用途变化与无效区域。未确认的行为不得标成完成。
6. 保存，关闭并重启，加载后重复查看与编辑。模拟无效或不支持的存档，确认运行城市未被破坏。

几何、引用、占用、变更和往返保存用针对性自动检查验证；输入、预览、操作流与视觉用实际游玩验证。第一阶段结束时填写下表，不能用类数量或编译结果替代：

| 项目 | 本轮状态 | 实施验收应记录 |
| --- | --- | --- |
| 道路与分区操作 | 已接入，实际鼠标体验未验收 | 已接近 / 差异 / 占位 / 未验证，附复现步骤 |
| 曲线、路口、重叠与道路修改 | 原作细节待核实 | 同场景原作与项目结果、剩余规则差异 |
| 实体与新存档 | 自动及原生重载检查通过，失败恢复继续补充 | 稳定引用、占用、重载与失败恢复结果 |
| 外部连接与道路视觉 | 当前原型有明显差距 | 简化部分、何时替换、实际可通行结果 |
| 建筑生长与经营 | 基础闭环已接入，完整经营未验收 | 不以手动建楼或人口缓存冒充完成 |

按上述最小范围逐步推进，并接入第二阶段必要的生长与经营闭环；不把所有系统一次推倒重写。分区规模、曲线形态和拆路后用途策略的原作对照仍待验证。
