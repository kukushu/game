## 家庭模拟与运行观察（当前版本 v4）

按 **F3** 或右侧“模拟观察台”开关面板。提供总览/账目、家庭/决策、住房/岗位、每日趋势、事件五页。可以暂停后推进一天，或用 20× 观察；1× 为 120 秒一天。家庭页显示稳定偏好、住所、雇主、储蓄、租金、估计通勤和最近候选评分，并可定位住所。读档恢复日内进度。

- 住宅菜单可选八户公寓和一户别墅；两者占地不同，建造后为空房，空置仍扣维护。
- 家庭按预算、技能、空间、私密性、通勤和储蓄偏好选择住所/工作。家庭各一名劳动者。默认每七天错峰评估，三十天租约；搬迁有成本和收益门槛。
- 人口来自实际家庭，收入来自实际收租；旧版住宅等级税收和自动升级在 v4 停用。普通商业/工业建设提供岗位，工资暂由简化外部经营收入支付。生活费/通勤费是外部支出，尚非闭合产业链。
- 满租且有可支付的意向时挂牌租金缓慢上涨，持续空置降价；已有租约锁价。房屋和岗位不能重复占用。道路改变后估计通勤缓存失效，家庭按评估周期响应；暂不含拥堵反馈。
- 按 0 选择住宅，展开住户中的个人，可查看姓名、年龄、当前状态、工作和目的地，并定位或跟随。青色菱形表示选中居民，位于建筑内时标在屋顶；上班和返程按日内时间沿道路推进。暂停会停住，读档恢复相同日程位置。每户仍仅一名劳动者；其他成员暂时在家，尚未模拟上学、购物或独立就业。
- 每户劳动者按 8:00–9:00 错峰八小时班次发起真实通勤任务；入口有车时等待发车，路上排队会延迟到岗，实际到达才进入建筑。青色标记与该居民车辆共用位置。日末按实际在岗分钟 / 480 结算工资；迁移启用当天也按剩余可出勤时间计薪。
- 实际上班耗时（含入口等待）进入当前住房/工作组合的评估；其他候选方案仍按畅通道路估算。道路修改后废弃旧观测，重新积累。出行中暂缓正常搬家/换工作；道路断开保留任务等待恢复，不靠超时删车制造到达。工作场所拆除后尝试沿道路回家。
- 每个道路出行任务都有独立车辆模型，显示数量没有固定上限；模型按需创建，到达后回收复用。模拟任务上限仍为 10048（原型面向几百户），背景货运最多 48 个任务，这些是派车限制，不会隐藏已出发的车辆。个人身份、行程、等待时间和已挣工资随存档保存。暂未实现步行、公交、多劳动者家庭和替代路线拥堵预测。
- 账目页显示财政和家庭资金核对差额，应均为零。趋势保留最近 180 天，事件最近 120 条。导出快照生成完整 JSON 和趋势 CSV，保存在 Unity 持久化目录下的 `SimulationReports`，界面通知显示具体路径。
- 旧城迁移保留道路、资金和住房位置；按原住宅等级初始化兼容公寓和合成家庭。人口不会因迁移凭空变化，但岗位口径变为每户一名劳动者，可能出现失业。旧代表性客运任务清理，货运保留。旧版没有居民个体历史，初始化偏好不代表恢复历史居民。
- 数值配置集中在 `HouseholdSettings`，并随存档保存。当前以几百户为目标，候选遍历和顺序轮换分配是原型实现；不是大规模市场清算器。公共服务仍显示容量，尚未进入家庭住房效用。

建议实验：暂停并导出基线 → 建住宅/增加岗位/修捷径 → 逐日推进 → 比较同一家庭的住所、雇主和候选评分，以及空置/通勤/租金趋势。不要用车辆多少判断居民多少。

检查：`Tools/Verify.ps1` 包含一年模拟的逐日资金、容量和状态检查；Unity 菜单 `Harbor > Validate household simulation` 验证旧存档 JSON、新存档续算和运行城市账目。

# 湾岸 / Harbor City

Unity 6000.6.3f1 + URP 城市建造原型。以《都市：天际线》的道路、分区、城市服务与经营循环为方向；地图、界面与建筑均由本项目代码生成。

产品方向为可商业发行的原创城市建造游戏；当前仍处于原型阶段，开发阶段和验收要求见 [产品路线](Docs/ProductRoadmap.md)。

## 运行

打开 `Assets/Scenes/SampleScene.unity`，点击 Unity Play。启动脚本自动生成一座示例城市，无需挂载组件。首次运行可能需要等待 URP shader 编译。建议将 Game 窗口最大化，以便阅读界面。

## 操作

| 操作 | 输入 |
| --- | --- |
| 移动视角 | 按住鼠标中键（滚轮）拖动地图，或 WASD / 方向键 |
| 缩放 | 鼠标放在地图上滚动滚轮；向上放大、向下缩小，以指针位置为中心，每格视野尺寸变化约 15% |
| 旋转 | 按住鼠标右键左右拖动，或 Q / E；拖动后保留当前建造工具 |
| 俯仰 | 按住鼠标右键上下拖动；向上拖放低视角，向下拖抬高俯瞰，范围 20°–80° |
| 自由道路 | 按 1，点击起点、终点；继续点击可延伸；端点与道路自动吸附 |
| 建筑 / 分区 | 左键 / 拖拽，仍使用方格地块 |
| 道路撤销 | 道路面板“撤销上一笔道路” / Ctrl+Z；退还该笔施工费用 |
| 工具 | 1 道路、2 住宅、3 商业、4 工业、5 电站、6 水塔、7 公园、8 拆除 |
| 取消工具 | 地图内右键单击（松开时取消）/ Esc |
| 查看车辆 | 按 0 / Esc 或点击“查看车辆与路线”，再左键点击车辆；黄色线表示剩余路线 |
| 暂停与继续 | 空格 / 界面按钮 |
| 加速、保存、读取 | 界面按钮 |

道路必须连通地图西侧入口。分区和服务设施按临街位置连接最近道路（中心线距离不超过 3.85 米），建筑不可侵占路面。电站、水塔各提供 160 单位容量，每级建筑消耗 1 单位容量，建筑最高 3 级。供给充足且人口与就业平衡时，分区自动发展。每个游戏日为正常速度下 2.5 秒；城市收取税收并支付维护费。公园改善幸福度，工业和失业降低幸福度。

保存位置：`Application.persistentDataPath/harbor-city.json`。保存保留前一版本 `.bak`；读取会替换当前城市。无存档或格式错误时保留当前进度。退出 Play 不会自动保存。

## 代码与检查

- `Assets/CityModel.cs`：不依赖 Unity 的道路连通、建造、城市增长、经济和存档数据规则。
- `Assets/CityTraffic.cs`：独立交通模拟、建筑出行任务、道路寻路、跟车让行、商品库存与往返流程。
- `Assets/CityRoads.cs`：道路节点、路段、吸附、交叉切分、施工校验与按行驶时间寻路。
- `Assets/CityRoadView.cs`：连续路面、路肩、接头和标线 Mesh。
- `Assets/HarborCityRoadTool.cs`：两次点击施工、预览、拆路与撤销操作。
- `Assets/HarborCityGame.cs`：运行时场景生成、镜头、输入、中文 HUD 和文件存档。
- `Assets/CityLandscape.cs`：Unity Terrain 高度图、TerrainCollider、4 层地表混合及道路贴地采样。
- `Assets/Resources/HarborCity/Terrain.mat`：显式引用 URP Terrain/Lit；独立构建仍需验证 shader 变体。
- `Assets/Editor/CityLandscapeChecks.cs`：Play 模式下通过 `Harbor > Validate terrain` 检查地形，报告输出到 `Temp/CityLandscapeChecks.txt`。
- `Tools/CityModelChecks.cs`：14 项模拟回归检查。
- `Tools/TrafficChecks.cs`：跨地图出行、返程、断路绕行与恢复、货运库存、跟车和长期运行检查。
- `Tools/RoadChecks.cs`：自由铺路、交叉路口、建筑接入、行驶中切分道路、施工失败与旧城市迁移检查。

在项目目录执行 `powershell -ExecutionPolicy Bypass -File Tools/Verify.ps1`。如 Unity 安装位置不同，传入 `-UnityData '安装目录/Editor/Data'`。

## 当前范围

这是核心玩法原型。已有 Terrain 丘陵、缓坡、海岸、坡面道路和建筑地基；陡坡禁止新建。道路支持任意角度直线铺设、端点吸附和自动交叉路口；建筑仍是网格地块。交通现按建筑产生代表性通勤、购物、配送、进口与出口任务，沿完整道路路线行驶；车辆分方向靠右行驶，有基础跟车间距和路口互斥让行。供水供电采用全城容量模型，没有管线与电网。尚未实现地形编辑保存、桥隧、公共交通、教育医疗消防、完整产业链、地块解锁、破产流程或完整资产系统。幸福度目前为反馈指标，不影响迁入或税率。道路断开时建筑保留，但不计入有效人口、岗位与税收。旧城市存档可以继续载入，地形资源在运行时生成，编辑模式的手动 Terrain 资源不会被覆盖。

## 自由道路第一版

- 选择道路后点击起点、终点，确认后可继续延伸。右键单击 / Esc 先撤回当前起点，再按一次退出工具；拖动右键仍旋转视角。新路使用独立节点和路段，不再受建筑方格方向限制。
- 端点优先吸附附近道路节点，其次吸附路段中间。同一平面相交会切分旧路并建立路口，正在行驶的车辆同步转换路线进度。当前提供一种 2.7 米宽的双向两车道占位道路，尺度后续需要统一调整。
- 预览显示长度、施工费用和最大纵坡。成本每 3 米 ¥100（总价向上取整），无效施工不扣费。纵坡上限 35%，横向高差上限 0.95 米；这些是原型玩法参数，不是现实道路设计标准。禁止水面、侵占建筑或分区、过短路段、过近路口、尖角和重叠道路。
- 点“撤销上一笔道路”退还该笔费用，只撤销新建路段，不倒退城市时间、车辆或建筑状态。路口处留下的细分节点继续使用。读取、拆路或脚本重载会清空施工撤销记录；不提供拆除撤销。
- 拆除工具点击路面会删除直到转弯或路口为止的一段直路，费用 ¥40；西侧入口连接段保留。
- 存档升级为 v2，保留建筑地块与交通任务，并独立保存道路节点、路段及高度。读取旧 v1 存档会从道路格子迁移网络；旧节点编号保持一致，已有车辆路线可继续使用。
- 尚无曲线、道路拓宽、单行道、桥隧、挖填方和沿路旋转的分区。建筑通过最近路段上的明确节点接路，尚未绘制独立车道出入口。路面横坡随地表，复杂路口仍使用简化接头和互斥让行。

## 交通原型规则

- 白色车通勤，蓝色车购物，橙色车运货；选择车辆可查看出发地、目的地、任务、载货和等待状态。到达后停留，再回到原来的建筑或城外入口。
- 建筑连接最近道路上的明确出入口节点，道路按长度 / 速度使用 Dijkstra 寻路。双向道路以行驶方向区分车道；不支持单行道、多车道换道或交通灯。
- 工业每 2 个模拟秒生产每级 1 单位商品，库存最多 24；商店低于 8 时请求一车 8 单位的配送，优先尝试本地工厂，否则进口；工厂库存达到 20 时可出口。货物发车时从供应方扣除，到达才入库，购物到达才消耗 1 单位。该库存尚未参与税收、原料成本或建筑成长计算。
- 每栋住宅最多各有一个通勤和购物往返任务；出发冷却分别为 45、30 个模拟秒，目的地停留分别为 10、4 秒，装卸停留 2 秒。它们是建筑需求的代表性车辆，不是逐个居民的上下班日程；城市财政日仍为 2.5 秒。
- 同时最多 48 个任务，轮流扫描建筑派车；达到上限会推迟出行，不会凭空完成订单。没有可达路线的需求暂不发车。途中拆路会在道路节点重新寻路，无路则等待；脚下道路被拆除时车辆暂停显示，恢复道路后继续，不能跳到其他道路。
- 无法移动或无法返程持续 120 个模拟秒后计为失败并释放任务。未送达货物退还仍存在的供应方；失败不是送达。路口采用保守的互斥让行，复杂密集路网仍需后续改进。
- 交通使用 20 Hz 固定步长，并跟随游戏内暂停和 1× / 3×。任务、路线进度、库存、冷却与累计结果随城市保存；旧 v1 存档缺少交通数据时初始化新交通。尚无停车场、步行实体、个人岗位匹配和交通拥堵对财政的反馈。
